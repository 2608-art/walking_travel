# 장소 운영시간 자동 점검

이 기능은 GitHub Actions에서 공개 출처를 정기적으로 확인하고, 검토할 내용을 GitHub 이슈에 모은다. 컴퓨터를 켜둘 필요가 없으며 ChatGPT 구독을 사용해 실행하지 않는다. **앱 데이터 수정과 Sites 배포는 자동으로 하지 않는다.** 이슈를 검토해 현행 운영정보를 확인한 뒤 요청하면 장소 데이터 수정·검증·배포를 별도로 진행한다.

## 대상과 실행 시각

| 실행 | 대상 | 한국 시간 |
| --- | --- | --- |
| 주간 | 목포·강릉·경주의 문화/전시·체험·음식점·카페 | 매주 화요일 09:17 |
| 월간 | 세 지역의 나머지 장소(산책·시장·책방 등) | 매월 1일 09:23 |
| 수동 | GitHub Actions의 `Place hours review` → `Run workflow`에서 주간·월간 선택 | 실행할 때 |

지역마다 별도 JSON 보고서와 `운영시간 점검` 이슈를 만든다. 강릉·경주는 현재 앱에서 공개 전이므로 이슈에도 그 상태를 표시한다. 첫 실행은 출처별 초기 기준을 기록한다. 이후 실행은 같은 이슈에 **새로 달라진 출처 문구·조회 상태**만 덧붙인다. 전체 결과는 해당 GitHub Actions 실행의 JSON 보고서에서 볼 수 있다.

## 무엇을 비교하는가

각 장소의 기존 `scheduleText`·`closureText`를 함께 싣고, 운영 주체의 공식 URL이 있으면 우선한다. 지자체·공공기관·운영사 공식 페이지를 먼저 확인하고, 해당 출처가 없을 때 기존 다이닝코드 장소 페이지를 보조로 확인한다. 카카오맵 장소 페이지는 자동 접근이 제한되어 직접 읽지 않는다. 출처 페이지의 시간·휴무 관련 문구를 수집하고, 이전 점검 때 수집한 문구와 비교한다.

이 결과는 **변경 후보**다. 페이지가 바뀌어도 실제 시간이 그대로일 수 있고, 공식 페이지에 시간이 보이지 않아 `시간 문구 추출 실패`로 나올 수 있다. 공개 출처 자체가 없거나 조회가 제한된 장소도 표시한다. 한 주의 날짜별 휴무를 정기휴무로 복사하지 않으며, 출처 충돌·임시휴무·기상 통제·마지막 주문이나 입장 시간은 검토할 때 따로 확인한다. 원문 전체 대신 관련 발췌 문구만 이슈·JSON 보고서에 보존하며 앱에는 자동 적용하지 않는다.

## 앱에 반영할 때

검토가 끝난 변경은 지역별 `public/places.json`, `public/gangneung-places.json`, `public/gyeongju-places.json`의 구조화된 운영정보와 표시 문구에 반영한다. 특정 날짜의 검증된 예외는 장소의 `dateHours`에 `YYYY-MM-DD` 키로 저장할 수 있다. 예를 들어 `{"2026-10-12":{"closed":true}}` 또는 `{"2026-10-13":{"open":"10:00","close":"16:00"}}` 형태다. 출처와 확인일도 함께 기록하고 추천·계획표의 시간 판정을 검사한다.

배포된 데이터를 불러온 뒤 **새로 생성하는 추천 루트**는 갱신된 운영정보로 다시 계산된다. 이미 열어 둔 코스 결과나 기기에 저장한 개인 계획은 자동 수정하지 않는다. GitHub 저장소의 변경만으로 Sites 배포가 일어나지 않으므로 앱에 반영하려면 별도 배포가 필요하다.
