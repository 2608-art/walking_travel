# 예산 대비 실제 지출 분석

사용자가 2026-11-17 선택한 지출 건별 항목·금액·이유 입력 방식. 계획표의 ‘여행 후 · 실제 지출 기록과 분석’에서 사용한다.

- 범위: 1번과 같은 현지 하루 식비·카페·현지 교통·입장/체험료, 일행 전체 원화 금액. 지출 내용과 금액은 필수, 이유는 선택. 0원 허용, 음수·소수·빈 금액은 거부한다.
- 비교 기준: 현재 예상 비용과 총예산·인원·여행일을 복사해 저장한다. 이후 일정·가격·예산 변경과 분리하며 교체는 확인 후 수행한다. 예상의 미확인 건수도 보존한다.
- 지출 입력 완료 전에는 차이의 절감/초과 판단을 보류하고 현재 기록액을 보여준다. 총예산을 이미 넘긴 경우 초과는 표시한다. 항목별 실제가 0원이라는 확인은 입력 완료 체크로 받는다.
- 실제−예상 > 0이면 초과, < 0이면 절감. 예상 미확인 항목의 차이 및 그 합계 차이는 판단 보류. 총예산−실제 잔액은 별도 지표다.
- 추가·수정·삭제하면 입력 중 상태로 전환한다. 비교 기준 교체와 지출 삭제는 확인 단계를 둔다. 이유는 사용자 메모이며 인과관계를 자동 추정하지 않는다.
- 기존 계획 필드/저장 키를 유지하고 `spending`만 선택적으로 추가한다. 예산 비활성화 중에도 지출을 볼 수 있다. 예전 계획에는 빈 상태를 표시한다. JSON 내보내기·가져오기 및 도시별 저장을 그대로 사용한다. 읽을 수 없는 지출 자료는 오류를 표시하고 원본을 덮어쓰지 않는다.

검증: `node scripts/verify-spending.mjs`, 예산 단위·저장 호환, Worker/SQLite, 경주 방문·혼자 여행, 테마 갱신·계획표 동선·경로 품질·요일 테마. 브라우저에서 실제 입력/수정/삭제/복원·고정 기준·미완료 판단·모바일 390px·HTML 문자 이스케이프 확인. 기존 외부 경로 API는 로컬 503 대역이며 실시간 가용성을 새로 검증한 것은 아니다.
