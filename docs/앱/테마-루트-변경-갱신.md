# 테마 루트의 장소 변경 반영

2026-10-08 기준 로컬 구현. GitHub 저장소는 장소 자료의 원본이며, 사이트는 별도 빌드·배포 결과입니다. 앱이 실행 중 비공개 GitHub를 조회하거나 길찾기 API를 호출해 테마를 재계산하지 않습니다.

## 배포 준비 절차

1. 조사자가 목포·강릉·경주의 장소 JSON을 근거 출처와 확인일을 포함해 갱신합니다. 폐업·장기 공사·일시 폐쇄는 아래 `availability` 형식으로 기록합니다.
2. `npm run build`가 이전 빌드 때 저장한 [입력 스냅샷](../../public/theme-route-updates.json)과 장소 자료를 비교합니다. 사진·가격만 바뀌면 저장 루트를 재계산하지 않습니다. 방문 가능 기간·휴무 날짜와 요일·운영시간·좌표 또는 폐업·공사 관련 문구가 바뀐 테마만 검사합니다.
3. 영향받은 날짜·요일에 방문할 수 없는 장소를 빼고, 같은 테마 후보 중 같은 분류이며 실제 보행 길로 30분 이내인 저장 장소를 찾습니다. 후보의 계산 가능한 운영시간이 없으면 자동 대체하지 않습니다. 도보 길선은 빌드 시 보행 API로 새로 확인하고 [변경 루트 JSON](../../public/theme-route-updates.json)·[GeoJSON](../../public/theme-route-updates.geojson)·[GPX](../../public/theme-route-updates.gpx)에 저장합니다.
4. 빌드가 [변경 루트 검사](../../scripts/verify-theme-route-updates.mjs)를 통과해야 사이트 산출물을 만듭니다. 앱은 선택 날짜에 변경 루트가 있으면 이를 우선 보여주고, 공사 기간 밖에서는 기존 요일별 저장 루트를 사용합니다.

```json
"availability": {
  "status": "construction",
  "from": "2026-10-15",
  "through": "2026-11-30",
  "source": "https://example.org/official-notice",
  "checkedAt": "2026-10-08"
}
```

`status`는 `closed`, `permanently_closed`, `construction`, `suspended` 중 하나입니다. 영구 폐업은 `through`를 생략합니다. `from`·근거 URL·확인일이 없거나 기간이 잘못된 자료는 빌드가 실패하도록 했습니다. 조사 근거가 단순 문구로만 바뀌고 적용 날짜를 구조화하지 못한 경우에는 기간을 추정해 자동 제외하지 않고 **재검토 필요**로 저장합니다.

## 추천 표시 기준

- 변경 뒤 4곳 이하는 해당 날짜의 테마 추천을 중지하고 사유를 표시합니다.
- 5~7곳은 길선을 저장하고 루트를 보여주되 **재검토 필요**로 표시합니다.
- 8곳 이상은 보행 길선·버스 횟수·점심과 저녁·카페 수·저장 운영시간을 이용한 예상 방문시각 검사를 통과해야 추천 상태로 표시합니다. 테마 제목에 실제 장소명이 들어가 있고 그 장소가 빠지면 방문지 수와 관계없이 **재검토 필요**입니다. 권역명만 있고 정확히 일치하는 장소명이 없으면 이 제목 검사는 적용하지 않습니다.
- 새 길선·출입구·승하차·운영시간을 확인할 수 없으면 추정 연결선을 만들지 않고 사유를 표시합니다. 버스 30분 기준은 탑승 시간에만 적용하고 정류장 접근 도보와 합산하지 않습니다. 확인되지 않은 버스 탑승 시간을 30분 이내로 간주하지 않습니다.

## 검증 범위

예상 방문시각은 테마의 기존 출발 시각과 분류별 기본 체류시간으로 계산합니다. 이는 여행 당일 예약·임시휴무·대기·현장 출입을 보증하지 않습니다. [격리된 변경 시험](../../scripts/verify-theme-route-refresh.mjs)은 불국사 공사로 인한 추천 중지, 같은 테마의 저장 후보 자동 대체, 변동이 없는 두 번째 빌드의 파일 재사용을 확인합니다. 공개 사이트 반영은 별도 배포 단계입니다.
