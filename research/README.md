## 이용 중 경로 저장 규칙 (2026-10-06)

가까운 570방향은 조사 우선순위다. 완성된 경로 570건을 뜻하지 않는다. 사용자가 이용하는 등록 장소 간 도보는 실제 길선 응답을 영구 저장하고 다시 쓴다. 버스는 현재 조회 시점의 단일 노선과 승하차 정류장이 확인되면 그 방향·노선·정류장 조합의 탑승시간을 저장한다. 첫 관측은 평균이라고 부르지 않는다. 반복 조회에서 기준 대비 5분 이상이면서 20% 이상 길면 이번 탑승시간을 사용하고 원인은 단정하지 않는다. 그 밖의 작은 차이는 저장 평균을 갱신한다. 정류장 도보를 더하되 배차 대기는 자동 코스 시간에 넣지 않는다. 조회 실패 시 저장 기준으로 안내하되 현재 상태 미확인을 표시한다. 공식 정류장 ID·좌표·개별 시간표 링크가 확인된 구간만 별도의 승인 버스 목록에 올린다.

사용자의 저장 지시에 따라 목포역→물망초·인스파이어링 커피·대명춘·웨이브 **4방향의 카카오 API 도보 길선**을 `public/walk-paths.json`에 저장했다. 2026-10-04 D1 응답의 길선·거리·시간을 사용했고, 2026-10-06 카카오맵 화면에서 거리·시간이 동일한 것을 확인했다. 네이버의 값은 별도 비교 자료이며 저장 길선의 출처로 쓰지 않았다. 각 저장 항목에는 당시 카카오 길찾기 URL과 확인 날짜를 남겼다. 실제 출입구·현장 보행 환경은 미확인이다. 혹호 방향은 거리·시간만 조사됐고 길선이 없어 운영 목록에 넣지 않았다. `public/bus-legs.json`의 확정 구간은 여전히 0건이다. 기존 D1의 나머지 캐시는 앱 서버에서 재사용하지만 세 지도 서비스의 현재 교차 검증으로 표현하지 않는다. 웨이브의 네이버 결과는 장소 POI가 아닌 `수문로 15-2` 주소 검색값이다.

## 조사 범위

[`nearby-candidates.json`](nearby-candidates.json)은 [`../public/places.json`](../public/places.json)에서 경위도가 있는 등록 장소 113곳과 앱의 등록 출발·도착점인 목포역(`station`)을 합친 114곳 각각에서, 직선거리로 가장 가까운 다른 장소 5곳을 정렬한 **방향별 조사 후보 570건**이다. 동률은 장소 ID 순서로 정한다. 이는 조사 순서를 정한 자료이며 이동 가능성, 실제 거리, 소요시간, 버스 운행을 검증한 결과가 아니다. 역방향은 별개의 구간이다.

바다·언덕·담장·출입구 때문에 직선거리가 짧아도 실제 길은 멀거나 없을 수 있다. 특히 고하도와 육지 사이 후보는 직선이 바다를 가로지른다. 지도에서 실제 보행로와 대중교통 연결을 확인하고, 갈 수 없는 수단은 `unavailable`과 이유를 기록한다. 가까운 다섯 후보는 도보가 가능해도 버스 존재 여부를 조사하며, 버스가 있으면 두 수단 모두 기록한다. 후보에 없는 구간은 향후 API 조회 대상으로 남긴다.

2026-10-06 읽기 전용 [기존 도보 캐시 대조](d1-cache-coverage-2026-10-06.json)에서 570개 후보 중 66개 방향이 이전 API 응답과 좌표 키가 정확히 일치했다. 예를 들어 노적봉→목포근대역사관 1관은 핀 사이 직선 43m이지만 당시 저장 도보 응답은 430m·9분이었다. 이는 우회 가능성을 보여주는 우선 조사 사례이며 현재 출입구와 경로 유효성은 다시 확인해야 한다. 앱 공개 도보 목록에는 목포역 출발 4방향만 넣었다.

## 지도 조사 순서

1. 후보의 출발·도착 **정확한 장소 핀과 출입구**를 확인한다. 지도 검색이 다른 지점을 반환하면 그 사실을 남기고 거리를 확정하지 않는다.
2. 네이버지도·카카오맵을 웹/앱 화면에서 수동 조회한다. 구글지도는 교차 확인에 활용한다. 이 단계의 지도 비교에는 API를 사용하지 않는다. 각 서비스에서 조사한 값과 출발 시각을 따로 기록하고 숫자를 혼합하지 않는다.
3. 도보에 대해 실제 경로, 거리, 시간, 주요 우회·계단·해상 장벽을 대조한다. 서비스별 경로가 다르면 어느 길을 선택했는지와 이유를 남긴다. 화면에 보이는 거리·시간만으로 지도 위 길선을 만들지 않는다.
4. 버스가 있는 후보는 **추천 버스 번호, 타는 정류장과 내리는 정류장의 이름·정류장 ID·좌표**, 장소에서 정류장까지/정류장에서 장소까지의 도보, 평균 탑승 시간, 환승, 운행 방향을 기록한다. 정류장 ID·좌표를 검증할 수 없으면 `null`로 남겨 검증 전 상태로 표시한다. 시간표 중심으로 운행하는 버스는 공식 시간표·운행 공지 링크를 우선 찾아 확인 날짜와 함께 저장한다. 자동 코스 시간은 확인된 정류장 도보와 평균 탑승시간을 더하며 별도 대기 여유는 넣지 않는다. 실제 대기와 배차 변동은 화면에서 안내한다.
5. 서로 다른 지도 결과, 조사 날짜·시각, 링크/화면 증거, 신뢰도를 검토한 뒤 승인된 구간만 앱의 저장 자료로 옮긴다. 자동 코스에 넣을 버스 구간은 양쪽 정류장 도보 거리·시간까지 확인해야 한다. 최신 운행 여부와 정류장 위치는 사용 전에 다시 확인한다.

구간별 조사 기록에는 최소한 `fromId`, `toId`, 양쪽 확인한 출입구·좌표, 이동수단, 각 지도 서비스의 URL, 조회 시각·출발 시각·거리·시간, 선택한 경로와 선정 이유, 교차 확인 결과, 미확인 사항, 검토자·검토일을 남긴다. 버스는 노선 번호와 승하차 정류장 정보, 정류장 접근/이탈 도보, 평균 탑승 분, 환승 여부, 확인 가능한 공식 시간표·운행 공지 링크를 추가한다. 출처를 열 수 없는 값이나 지도 사이의 차이를 임의로 평균 내지 않는다.

공식 링크 조사의 시작점은 [목포시 시내버스 공지 목록](https://www.mokpo.go.kr/www/life_welfare/traffic/city/notice)과 [목포시교통정보센터](https://its.mokpo.go.kr/)다. 2026-10-06 목록에는 2026-08-31 기준 시간표 변경, 2026-08-10 기준 낭만버스 변경, 2026-09-01 광역급행버스 신설 등 서로 다른 공지가 보인다. 노선별 적용 공지와 그 이후의 변경을 확인한 뒤 해당 구간에 맞는 개별 링크를 저장한다. 목록 자체를 특정 구간의 운행 증거로 사용하지 않는다.

## 도보 길선

정확한 길선을 제공할 수 있는 경우, 사용자나 조사자가 제공한 GPX를 [`../scripts/import-walk-gpx.py`](../scripts/import-walk-gpx.py)로 **검토 전 초안**으로 변환할 수 있다. 카카오맵에서 적법하게 내보낼 수 있는 GPX가 있으면 그 파일을 사용할 수 있다. 수동 조사로 길선 좌표를 얻을 수 없는 경우에만 기존 경로 API의 좌표 형상을 대안으로 검토한다. GPX·API 중 어느 쪽이든 출처, 방향, 양쪽 출입구, 길선과 표시 거리·시간을 사람이 확인한 뒤 [`../public/walk-paths.json`](../public/walk-paths.json)의 `paths` 형식으로 승인·반영한다. 임의의 직선 또는 지도 화면만 보고 그린 선을 실제 도보 경로처럼 저장하지 않는다.

예시: `python scripts/import-walk-gpx.py --gpx 경로.gpx --from p2 --to p8 --source-label 카카오맵 --source-url https://example.com/route --meters 100 --minutes 2 --out research/drafts/p2-p8.json` (실제 파일·출처·값으로 바꿔 실행). 도구는 GPS 점의 방향과 양 끝 좌표를 검사하며 공개 경로 목록을 수정하지 않는다. 생성된 거리·시간은 입력한 조사값이고 GPX에서 자동 확정한 값이 아니다.
