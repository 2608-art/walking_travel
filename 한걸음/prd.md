- 추천 루트의 우선 목표(사용자 확인): 하루 동안 한 동네를 가능한 한 넓고 풍부하게 둘러보되, 되돌아가는 이동을 줄인 효율적인 순서와 충분한 장소 정보를 제공한다. 추천 결과는 이용자가 계획표에서 취향과 체력에 맞게 수정할 수 있는 출발점이다. 방문 장소 수가 많다는 이유만으로 추천 코스를 낮게 평가하지 않는다.
- 실제 도보 시간 재검사(2026-10-04 사용자 확인): 운영시간·종료 시각과 충돌하면 방문 순서를 먼저 조정하고, 그래도 불가능할 때 필수가 아닌 장소만 줄인다. 출발·도착, 꼭 가고 싶은 장소, 도보 상한은 유지한다. 같은 출발·도착을 금지하지 않으며 불가능한 코스를 억지로 만들지 않는다.
- 첫 화면(2026-10-04 디자인 변경): **여행지 이미지 카드**를 중심으로 스케치 배경·거북이·검색·여행 취향을 배치한다. 카드를 누르면 큰 이미지와 추천 루트·여행지·여행 정보 탭이 있는 지역 소개 화면을 연다. 지도 보기 버튼으로 해당 지역 지도를 연다. 현재 목포만 제공하며, 클린 UI 70 : 스케치 30의 참고 이미지 구성을 전체 화면에 적용한다.
- 시간 입력(사용자 확인): **몇 시부터 몇 시까지**를 기본으로 한다.
- 날짜 기준(사용자 확인): **시작 시각이 속한 날짜**를 일정의 기준일로 한다. 자정을 넘기면 화면에 `다음 날`을 명확히 표시한다.
- 종료 지점(사용자 확인): 사용자가 선택할 수 있으며 **`선택 안 함`**도 제공한다. 선택하지 않으면 마지막 방문 장소에서 코스가 끝난다.
- 지역 제공(사용자 확인): 지역을 **하나씩 추가**한다. 현재 목포 자료로 첫 지역을 검토 중이며, 각 지역은 장소·교통 데이터 검증 후 공개한다.
- 출발 지점(사용자 확인): 이용자가 **직접 선택하는 것이 기본**이다. 지도에서 위치를 찍거나 장소·주소를 검색해 지정하고, `현재 위치로 설정`을 추천 선택지로 제공한다.
- GitHub 저장(2026-10-05 사용자 확인): 제작한 앱의 배포 소스를 [비공개 저장소](https://github.com/2608-art/walking_travel)에 올렸다. `main`은 Sites 버전 17 소스, `codex/spec`은 지도 변경과 Spec이다. 향후 코드 공개 여부와 이용자의 코스 저장·동기화 방식은 별도로 결정한다.
- 코스 저장(사용자 확인): 첫 버전은 로그인 없이 사용 중인 기기의 웹앱 저장 공간에 저장하고, 코스 내보내기·가져오기를 제공한다. 다른 기기와 자동 동기화하는 로그인 기능은 나중에 결정한다.
- 오프라인 이용(사용자 확인): 새 코스 계산과 지도는 인터넷이 필요하다. 인터넷이 끊기면 이미 저장한 코스의 계획을 **글로만** 볼 수 있다. 첫 버전에 오프라인 지도 다운로드는 넣지 않는다.
- 코스 탐색(사용자 확인): 각 코스에 명칭을 붙이고, 한 번에 한 코스의 상세 내용을 본다. 상세 상단의 작은 화살표로 다른 코스 목록을 펼쳐 홈으로 돌아가지 않고 전환한다.
- 시간계획표(사용자 확인): 시작 시각을 입력하면 그 시각부터 자정까지 시간대 칸을 만들고, 각 칸에서 직접 입력하거나 추천 장소 최대 3곳을 고를 수 있다. 추천 코스의 예시 시간계획표도 가져와 수정할 수 있다. 장소별 정보를 입력을 방해하지 않는 위치에 보여주고, 자료에 없는 장소도 직접 추가할 수 있다.
- 늦은 시간(사용자 확인): 대중교통이 끊기거나 추천할 장소가 없을 때도 이유를 설명하고, 가능한 도보 장소와 택시로 검토할 수 있는 장소를 구분해 보여준다.

## 추후 개발: 추천 루트에서 제외할 장소

- 사용자 아이디어: 추천 루트에서 가고 싶지 않은 장소를 지정해 제외할 수 있게 한다.
- 제외한 장소 때문에 걷는 대신 버스를 더 이용하게 될 수 있다는 경고를 함께 보여준다.
- 현재는 구현하지 않고 아이디어로 저장한다. 사용자가 아이디어 수집을 마친 뒤 검토를 요청하면 구현 방식과 우선순위를 논의한다.

## 1. 앱이 해주는 일

혼자 여행하는 사람이 지도에서 여행지를 살펴보고, 자신에게 맞는 방식으로 **하루 코스**를 만든다. 추천 루트는 하루 안에 해당 동네의 장소를 최대한 많이 즐길 수 있도록 효율적인 방문 순서와 장소 정보를 제공한다. 시작·종료 시간으로 찾거나, 꼭 갈 장소를 정하거나, 준비된 추천 코스를 둘러보거나, 장소와 방문 순서를 직접 정할 수 있다. 앱은 차 없이 다닐 수 있는 방문 순서와 제외한 이유를 보여준다. 이용자는 추천 결과를 자신의 취향과 체력에 맞게 수정한다.

사용자가 보게 될 중심 문장은 다음과 같다.

> “오늘 오후 2시부터 6시까지, 목포역에서 시작하면 이런 순서로 둘러볼 수 있어요.”

앱의 코스는 정해진 시간표를 따라 움직이는 여행 상품이 아니다. 장소별 체류시간은 범위로 제시하고, 입장 마감·교통편처럼 지켜야 하는 시각만 분명하게 보여준다. 원하는 이용자는 코스를 **예시 시간계획표**로 바꿔 보거나 직접 작성할 수 있다.

## 2. 첫 사용자 경험

1. **여행지 선택:** 홈에서 여행지·장소를 검색하거나 목포 이미지 카드를 누른다. 목포 소개 화면에는 큰 대표 이미지, 소개와 거북이, 추천 루트·여행지·여행 정보 탭이 있다. `목포 지도 둘러보기`를 누르면 목포 중심 지도와 여러 유형의 장소 핀이 보인다. 지도를 이동·확대·축소할 수 있으며 `목포로 돌아가기`를 누르면 지역 중심으로 돌아온다.
2. **지도 탐색:** 지도 위의 검색과 7개 유형 필터로 장소를 찾는다. 여러 유형을 함께 선택할 수 있고, 핀이나 장소 카드를 누르면 독립된 장소 상세 화면이 열린다. 하단 장소 패널에서 `계획표`·`추천 루트`로 들어가거나 상단에서 지도/목록을 전환한다.
3. **직접 계획:** `계획`을 누르면 시간계획표 화면이 열린다. 시작 시각을 입력하면 그 시각부터 자정까지 시간대 칸이 생긴다. 칸을 누르면 `입력`과 해당 시간대의 추천 장소 최대 3곳이 보인다. 기존 장소를 검색·선택하거나 직접 장소를 추가한다.
4. **추천 루트:** `추천 루트`를 누르고 출발 지점을 고른다. 필요한 날짜·시간 조건을 적용한 뒤 이름 있는 여러 코스를 본다. 한 코스를 선택하면 `시간계획표에 넣으시겠습니까?`를 묻고, 넣은 계획은 장소·시간·메모를 일부 수정하거나 삭제할 수 있다. 추천 코스가 없으면 이유와 가능한 도보·택시 대안을 본다.
5. **여행 중 이동:** 계획 시각은 예상이다. 이용자가 실제로 다음 장소로 떠날 때 해당 칸의 `이제 다음 장소로 이동`을 누르면 그 시각을 기준으로 지도 경로와 다음 장소의 운영시간·브레이크타임·마감 충돌을 다시 확인한다.

## 3. 화면 구성

첫 화면은 스케치 배경·검색·취향과 **여행지 이미지 카드**로 구성한다. 카드 선택은 독립된 여행지 소개 화면으로 이어진다. 지역을 더 추가할 때도 같은 카드 형식을 사용한다. 장소·교통 자료가 준비되지 않은 지역은 넣지 않는다. 지역 소개에서는 추천 루트·여행지·여행 정보 탭으로 탐색하고 지도나 계획표로 이동한다. 추천 루트 목록 맨 앞의 출발·도착 맞춤 카드에서 기존 맞춤 입력으로 바로 들어간다. 실제 사진과 제작 일러스트는 구분해 관리한다. 사용자 피드백에 따라 현재 목포 대표는 원래 풍경 일러스트로 복원했으며 유달산·역사관 1관 상세의 실제 사진은 유지한다. 다른 장소의 전용 이미지는 아직 준비하지 않았다. 기본 글꼴은 Pretendard, 홈 큰 문구·감성 섹션·지역명·팁 제목과 작은 말풍선에만 Cafe24 Dongdong을 사용한다. 장소명·운영시간·주소·설명·조작 UI는 Pretendard를 유지한다. UI 전체의 현행 기준과 이미지 등록 방식은 [디자인 기획](travel-app/디자인-기획.md)을 따른다.

지역 지도 화면에서는 지도 중심과 기본 확대 수준을 선택한 지역으로 맞춘다. 지도는 자유롭게 이동·확대·축소할 수 있고 `목포로 돌아가기`는 지역 중심으로 되돌린다. 모바일은 검색·유형 필터를 지도 위에, 장소 카드와 계획표·추천 루트 버튼을 하단 패널에 둔다. 넓은 화면은 왼쪽 탐색 패널과 오른쪽 지도로 나눈다. 음식점·카페·자연/산책·문화/전시·체험/탑승·시장/간식·책방/소품의 복수 선택은 합집합으로 적용하며 전체를 누르면 해제한다. 핀과 카드에서 장소 상세로 이동하고 지도/목록을 전환할 수 있다. 지도 전용 대표점은 실제 출입구·도보 계산 좌표와 구별한다.

지역 지도 화면의 큰 진입은 `계획`과 `추천 루트` 두 가지다. 기존에 논의한 `시간에 맞춰 찾기`·`꼭 갈 장소로 만들기`·`추천 코스 둘러보기`는 추천 루트 안의 조건과 탐색 방식으로, `직접 코스 만들기`는 계획 화면에서 장소와 순서를 직접 정하는 방식으로 제공한다. 결과 생성과 수정에는 **같은 시간 검증 규칙**을 사용한다. 이용자가 정한 방문 순서를 앱이 임의로 바꾸지 않는다.

| 추천 결과 | 각각 이름이 붙은 코스 목록. 예상 총 시간 범위, 장소 수, 걷기·대중교통 부담, 종료 예상, 확인 상태 | 코스 하나를 열거나 조건 수정 |
| 추천 결과 없음·심야 안내 | 확정 코스가 없으면 입력 위치와 주변 장소를 잇는 검토용 루트, 시간·영업·이동의 미확인 이유, 확인된 버스 탑승시간을 구분해 표시. 심야에는 검증된 도보권·교통 대안을 별도 안내 | 검토용 순서를 살펴보고 시간·장소 조건을 조정하거나 직접 계획하기 |
| 코스 상세 | 선택한 코스 하나의 장소 순서·이동·마감과 지도/목록. 상단의 `코스명 ▾`을 누르면 다른 코스 목록이 펼쳐짐 | 다른 코스로 즉시 전환, 예시 시간계획표 열기, 코스 저장·장소 바꾸기·출발 전 확인 |
| 시간계획표 | 추천 코스로 만든 예시 또는 직접 만든 계획. 시작 시각부터 자정까지의 칸, 방문·이동 순서, 장소별 안내, 이용자 메모, 항목 추가·수정·삭제, `이제 다음 장소로 이동` | 예시를 편집하거나 처음부터 작성해 저장하고 실제 출발 때 지도로 길 보기 |
| 장소 상세 | 큰 장소 이미지 영역, 장소명·위치, 지도/계획표/장소 정보 버튼, 방문 안내·운영시간·같은 유형 장소 탭. 미등록 이미지는 유형 이미지로 표시 | 지도로 위치 확인·계획표 열기·운영정보 확인 |
| 저장한 코스 | 저장 시 사용한 날짜·시작 시각·총 시간, 당시 추천 내용, 데이터 재확인 표시, 내보내기·가져오기 | 온라인에서는 다시 열고 재계산, 오프라인에서는 저장한 계획 글 열람 |

**코스명·요약 예시:** `원도심과 해안 산책 · 약 5~6시간 · 장소 4곳 · 도보+버스 1회`. 실제 코스 데이터가 검증되기 전의 표현 예시다.

## 4. 핵심 상호작용

### 시간을 바꾸면 바로 다시 판단

사용자가 10:00을 15:00으로 바꾸거나 하루 일정의 종료 시각을 앞당기면 같은 코스를 단순히 옮기거나 자르지 않는다. 입장 마감과 예상 체류시간을 다시 계산하고, 늦어서 갈 수 없는 장소를 교체하거나 코스를 짧게 만든다. 바뀐 결과에는 `15:00 시작이라 역사관 입장 마감 전에 관람을 마치기 어려워요`처럼 이유를 붙인다.

**날짜가 넘어가는 경우:** 예를 들어 `10월 1일 22:00 → 다음 날 02:00`은 10월 1일에 시작한 하나의 일정으로 다룬다. 코스 카드·상세·저장한 코스의 종료 시각에도 `다음 날 02:00`을 표시한다. 자정 이후 장소 운영은 실제 다음 날짜와 요일로 검사하고, 교통편은 해당 운행편의 **운행일 규칙**까지 확인한다. 날짜 표시가 바뀌어도 총 소요시간 계산은 연속된 4시간으로 처리한다.

### 출발 지점 선택

출발 지점은 지도에서 지정하거나 장소·주소를 찾아 **이용자가 직접 선택**한다. `현재 위치로 설정`은 별도의 추천 선택지로 보여주며, 누른 경우에만 위치 권한을 요청한다. 권한을 허용하지 않거나 위치 확인에 실패해도 직접 선택을 계속할 수 있다. 현재 위치가 제공 지역 밖이면 가능한 코스인 것처럼 표시하지 않고 지역 안의 출발 지점을 고르도록 안내한다.

### 사용자가 원하는 장소를 존중

가고 싶은 장소는 `꼭 가고 싶어요`와 `가면 좋아요`로 구분하는 방안을 제안한다. 꼭 가고 싶은 장소를 시간 안에 넣을 수 없으면 조용히 빼지 않고, 더 긴 코스·이른 시작·다른 장소 중 가능한 선택지를 보여준다.

### 직접 만든 코스는 사용자가 편집

`직접 코스 만들기`에서는 지도·검색의 장소를 선택하거나 이름을 글로 입력하고, 장소를 추가·삭제하거나 방문 순서를 바꿀 수 있다. 글로 입력한 이름이 기존 장소와 일치하면 확인을 받아 연결한다. 일치하는 장소가 없으면 사용자가 입력한 이름을 코스에 남기되 위치·영업·이동을 검증할 수 없다고 표시한다. 앱은 검증 가능한 구간의 도보·대중교통 연결, 예상 소요시간, 입장·주문 마감을 검사한다. 종료 지점을 고른 경우에만 그곳까지의 이동을 검사한다. 연결이 어렵거나 시간이 넘치면 해당 구간과 이유를 표시하고 대안 순서를 **제안**한다. 대안 적용 여부는 사용자가 결정한다.

### 시간계획표를 선택해서 사용

`계획`을 누르면 빈 시간계획표가 열린다. 시작 시각을 입력하면 **그 시각부터 자정까지 시간대 칸**을 만들고, 필요한 칸을 눌러 `입력`하거나 해당 시각에 방문을 검토할 수 있는 **추천 장소 최대 3곳** 중 하나를 고른다. 추천할 만한 장소가 3곳보다 적으면 실제 확인된 수만 보여주고 이유를 알려준다. 추천 장소를 누르면 해당 칸에 바로 넣고 시간계획표로 돌아온다. `입력`에서는 앱에 있는 장소명을 검색하면 후보를 보여주고, 선택하면 장소 정보가 연결된다.

추천 루트는 출발 지점을 고른 뒤 여러 코스에서 하나를 선택한다. 코스 상세에서 `시간계획표에 넣으시겠습니까?`를 묻고 동의하면 **예시 시간계획표를 복사**한다. 추천 결과가 가진 날짜·시작/종료 시간과 종료 지점 조건을 유지하며, 복사한 뒤에는 이용자가 장소·순서·시간·메모를 일부 수정하거나 삭제할 수 있다. 코스명 옆 화살표로 다른 코스를 보는 동작은 그대로 유지한다.

시간계획표의 시각은 예상값이다. 이용자가 시작 시각을 앞당기면 앞쪽 칸을 늘리고 늦추면 사라지는 앞쪽 칸을 확인한다. 예를 들어 09:00을 11:00으로 바꾸는데 09:00~11:00에 계획이 있으면 `옮기기 / 삭제하기 / 변경 취소`를 먼저 묻는다. `옮기기`를 고르면 다시 `모든 일정을 2시간 뒤로 밀기 / 사라지는 칸의 계획만 새 시간대로 직접 옮기기`를 선택한다. 겹치는 칸은 충돌을 표시하고, 변경 결과를 **적용 전에 미리보기**로 보여준다. 공식 마감·폐관·브레이크타임과 충돌해 삭제될 계획은 장소명과 이유를 보여주고 이용자가 삭제를 확인하도록 한다. 앱의 `폐관 1시간 전 입장 권장`만으로 계획을 삭제하지 않는다. 자정을 넘기는 줄은 `다음 날`로 표시한다.

앱에 있는 장소를 선택하면 입력칸을 가리지 않는 **짧은 장소 안내**를 해당 줄 아래에 표시한다. 운영 종료 시각과 공식 마지막 입장 시각이 확인되면 구분해 보여준다. 별도 공식 입장 마감이 없는 경우에는 `18:00 폐관 · 공식 입장 마감 정보 없음 · 17:00 이전 입장 권장`처럼 **앱의 권장 시각**임을 분명히 쓴다. 이 권장은 방문 가능 여부를 막는 조건으로 사용하지 않는다. 예를 들어 18:00 폐관 장소를 16:00에 방문하는 계획은 17:00 권장 시각을 이유로 제외하거나 `방문 불가`로 표시하지 않는다. 17:00 이후라도 공식 입장 제한이 확인되지 않았다면 권장 시각을 넘었다는 이유만으로 입력·저장을 막지 않는다. 예상 체류가 폐관 이후까지 이어지면 체류시간 단축이나 더 이른 시작을 **제안**한다. 운영시간이 불확실하거나 임시휴무 가능성이 있으면 해당 안내를 확정 정보로 표시하지 않는다. 입력을 막는 팝업은 사용하지 않으며, 긴 장소 설명은 펼쳐서 볼 수 있게 한다.

앱에 없는 장소도 `항목 추가`로 한 줄씩 넣는다. 각 줄에는 **이름**, **위치 정보**(지도에서 찍거나 주소·위치 설명 입력), **기타 메모** 입력칸을 둔다. 한 줄을 완성한 뒤 다음 줄을 계속 추가할 수 있고, 각 줄을 따로 수정·삭제할 수 있다. 위치를 지정해도 그 장소의 운영시간·입장 마감은 자동 확인된 것으로 취급하지 않는다. 위치가 없거나 이동 경로를 검증할 수 없으면 해당 구간의 시간·가능 여부를 미확인으로 표시하되 사용자가 적은 계획은 유지한다.

줄이 많아지거나 안내·메모가 길어지면 시간계획표 페이지를 **세로로 스크롤**해서 끝까지 볼 수 있다. 휴대폰에서는 시간과 입력칸이 화면 너비에 맞게 배치되고, 안내가 길면 줄바꿈·펼치기로 표시한다. 입력칸 안의 별도 긴 스크롤 때문에 다른 줄을 찾기 어려워지지 않게 한다.

### 다음 장소로 실제 이동할 때 길 보기

계획표의 시각이 됐다고 지도를 자동으로 띄우지 않는다. 이용자가 현 장소에서 더 머물거나 일찍 나올 수 있으므로, 준비됐을 때 **다음 장소 칸의 `이제 다음 장소로 이동`**을 누른다. 그때의 시각을 출발 기준으로 삼아 지도에 다음 장소와 이동 경로를 표시한다. 기본 출발점은 직전 계획의 장소이며, 원하면 `현재 위치에서 출발`을 선택할 수 있다. 도보와 검증된 대중교통을 구분하고, 경로를 확정할 근거가 없으면 임의의 선이나 버스편을 표시하지 않는다.

예상 도착 시각으로 다음 장소의 운영시간·브레이크타임·공식 입장/주문 마감·폐관을 다시 검사한다. 계획보다 늦게 나왔다고 다음 장소를 자동 삭제하지 않고, 기다리기·방문시간 조정·다른 장소 선택을 보여준다. 직접 넣은 장소는 위치를 지정한 경우에만 지도에 표시할 수 있다. 인터넷이 없으면 지도를 열 수 없고 저장한 계획 글만 볼 수 있다.

### 코스 사이를 홈으로 돌아가지 않고 이동

추천 코스와 저장한 코스는 각각 구분되는 명칭을 가진다. 한 코스의 상세 화면에서는 상단에 현재 코스명을 표시하고, 옆의 작은 화살표를 누르면 **같은 검색 조건에서 볼 수 있는 다른 코스 목록**을 펼친다. 다른 이름을 선택하면 상세 내용만 바뀌며 지도 홈으로 돌아가지 않는다. 날짜·시작/종료 시각·출발 지점·필수 장소 조건은 유지한다. 화살표는 작게 보이더라도 누르기 쉬운 영역과 `다른 코스 보기`라는 접근 가능한 이름을 갖는다.

### 이동은 이해하기 쉽게

각 구간을 `도보 약 12~18분`, `버스 이용·대기 변동`, `케이블카 운영 확인 필요`처럼 수단과 시간의 확실성을 함께 표시한다. 버스 번호와 정확한 승차시각은 검증된 구간에서만 보여준다. 기본 코스 화면에서는 **방문 순서와 지켜야 할 마감**을 먼저 보여주고, 시간대별 배치를 원하는 이용자에게 시간계획표를 제공한다.

### 불가능한 이유도 결과의 일부

맞춤 추천은 한 곳만 방문할 시간이 있어도 이동·운영·종료 조건을 통과하면 확정 코스로 보여준다. 확정 코스를 만들지 못해도 입력한 출발·도착·필수 장소와 주변 등록 장소를 잇는 **검토용 루트**를 지도와 방문 순서로 보여준다. 이 루트는 영업·종료 시각·실제 이동을 모두 통과한 추천이 아니며, 문제가 있거나 확인하지 못한 구간을 이유와 함께 표시한다. 실제 버스 탑승시간만 60분 이상이면 뚜벅이 여행 권역을 벗어난다고 안내한다. 정류장 도보·환승·배차 대기는 이 60분에 합산하지 않으며 별도로 표시한다. 탑승시간을 확인하지 못하면 60분 미만이라고 단정하지 않는다. 검토용 루트를 확정 코스처럼 시간계획표로 자동 복사하지 않고, 이용자가 조건을 바꾸거나 직접 계획하도록 연결한다.

### 늦은 시간에는 가능한 선택지를 구분

입력 시간대에 검증된 대중교통 코스가 없으면 그 이유를 먼저 말한다. 운행 종료가 확인된 경우에는 `이 시간대에는 이용할 수 있는 버스편이 확인되지 않았어요`라고 안내한다. 자료가 부족해 판단할 수 없는 경우에는 `버스 운행정보가 확인되지 않았어요`라고 구분한다.

그다음 **실제로 방문 가능한 시간인지 확인된 도보권 장소**를 보여준다. 해당 장소도 없다면 `현재 확인된 추천 장소가 없어요`라고 알려준다. 택시 대안도 입력 시간에 방문할 수 있는 것으로 확인된 장소만 대상으로 한다. 이동을 검토할 수 있는 장소는 별도로 표시하되, 배차 여부·대기시간·요금·현장 영업의 당일 변동은 확정하지 않는다. 택시 대안이 자동으로 대중교통 코스의 가능 판정을 대신하지 않는다.

## 5. 추천이 동작하는 방식

출시 전에 AI가 장소 묶음, 추천 순서 후보, 설명 문구, 누락·충돌 후보를 준비하고 사람이 검수한다. 검수된 장소·이동 데이터와 코스 후보를 앱에 넣는다. 사용자가 어느 시작 방식을 택하든 **같은 앱 내부 시간 계산 규칙**이 날짜·시작/종료 시각·장소 조건을 검사한다. 직접 만든 코스에서는 후보를 고르는 대신 사용자가 정한 순서의 가능성을 검사한다. 사용자 이용 중 실시간 AI 호출은 필요하지 않다.

추천 코스는 방문 장소 수뿐 아니라 여행자가 실제로 걷는 순서도 비교한다. 현재 위치에서 가까운 다음 방문지를 지나쳐 먼 곳에 갔다가 돌아오거나, 앞서 방문한 동네로 불필요하게 되돌아가는 후보에는 불이익을 준다. 같은 블록에 붙은 장소를 드나드는 짧은 왕복은 문제로 보지 않는다. 우회가 운영시간·확정한 식사 시각·필수 방문 때문에 필요한 경우에는 해당 조건을 지키며, 순서를 바꾼 코스는 실제 도보 구간과 운영·도착 시각을 다시 확인한다. 같은 조건의 여러 후보는 방문 가치와 동선 부담을 함께 비교해 보여준다. 이 기준은 추천 코스에 적용하며 이용자가 직접 정한 방문 순서를 임의로 바꾸지 않는다.

앱은 사용자가 고른 **출발 지점에서 첫 장소까지의 이동**, 장소의 운영·마감 시간, 계획 체류시간, 장소 간 이동과 대기를 합산한다. 종료 지점이 선택되면 마지막 장소에서 그 지점까지의 이동도 합산한다. `선택 안 함`이면 마지막 장소에서 방문을 마치는 시각까지만 계산하고, 귀가·다음 목적지 이동은 포함하지 않았음을 결과에 표시한다. 직접 고른 출발 지점에서 검증된 보행·교통 연결을 만들 수 없다면 코스를 확정 가능한 것으로 표시하지 않고 이유를 알려준다. `도착이 마지막 입장보다 늦음`, `관람을 마치기 전에 폐관`, `총 시간이 초과됨`, `선택한 종료 지점으로 갈 편 확인 불가`는 서로 다른 이유로 다룬다. 일부 값이 추정이면 결과에도 그 사실을 보인다.

가능 여부의 기준은 확인된 운영시간·**공식** 마지막 입장 시각·교통 운행 조건·이용자가 설정한 시간이다. `폐관 1시간 전 입장 권장`처럼 앱이 만든 권장 시각은 안내로만 사용하며, 코스나 시간계획표의 입력·저장·가능 판정을 차단하지 않는다. 계획한 체류가 운영 종료를 넘으면 그 충돌을 설명하고 시간 조정을 제안한다.

운영시간·브레이크타임·공식 입장/주문 마감의 판정 순서와 실제 이동 시 재검토 동작은 [시간 검증 규칙](docs/앱/시간-검증-규칙.md)을 따른다. 이 규칙은 추천 코스와 이용자가 만든 계획표에 공통 적용한다.

사전 준비된 코스 **문장만** 저장하면 모든 시작 시각 변화에 대응하기 어렵다. 앱에는 장소와 구간의 구조화된 조건도 함께 넣어야 한다.

## 6. 신뢰와 최신성

- 추천 카드와 상세 화면에 `운영정보 기준`, `방문 전 확인 필요` 등 확인 상태를 짧은 말로 표시한다. 색만으로 상태를 구분하지 않는다.
- 장소의 임시휴무, 버스 지연·결행, 배편·케이블카의 날씨 영향은 사전 데이터만으로 당일 보장할 수 없다. 바뀔 가능성이 있는 항목은 출발 전 확인 목록에 모은다.
- 공식 자료끼리 충돌하거나 현행 운항편을 확인하지 못한 코스는 확정 추천에 넣지 않는다.
- 저장한 코스를 다시 열 때 오래된 운영정보를 그대로 확정 정보처럼 보여주지 않는다.

### 저장한 코스

첫 버전의 저장한 코스는 **현재 기기의 브라우저·설치형 웹앱 저장 공간**에 보관한다. 계정을 만들거나 서버에 이용자 코스를 저장하지 않는다. 같은 기기에서 다시 열어 수정할 수 있지만, 다른 기기와 자동으로 동기화되지 않는다. 저장한 코스를 파일로 **내보내고 가져와** 직접 백업·복원할 수 있다. 가져온 코스는 현재 데이터로 다시 검토하며, 기존 저장 코스를 사용자 확인 없이 지우지 않는다. 브라우저·앱 데이터를 지우거나 앱을 삭제하면 내보내지 않은 코스가 사라질 수 있음을 저장 화면에서 안내한다. 웹사이트로도 이용할 수 있으므로 `설치한 사람만 접근 가능`을 보안 제한으로 약속하지 않는다. 공용 기기에서는 그 기기의 같은 브라우저를 사용하는 사람이 저장 내용을 볼 수 있다.

인터넷이 없어도 이미 저장한 코스·시간계획표의 명칭, 날짜·시간, 방문 순서, 장소, 이용자 메모, 저장 당시 이동 안내와 주의사항을 **글로** 열어볼 수 있다. 이때 지도는 보여주지 않고 새 코스 계산·재계산도 제공하지 않는다. 새 운행·휴무 정보를 확인할 수 없으므로 저장 당시 기준일과 `오프라인·최신 정보 확인 불가`를 표시한다. 첫 버전에는 지도 데이터 다운로드 기능을 넣지 않는다.

## 7. 첫 버전 범위

지역은 **하나씩 추가**한다. 현재 첫 적용 후보로 목포의 하루 계획을 검토한다. 추천에는 도보와 **검증된 대중교통**을 함께 사용할 수 있어야 한다. 실제 공개 지역과 코스는 장소·정류장·운행·귀환을 연결해 확인한 범위로 한정한다. 검증되지 않은 버스·케이블카·여객선 구간을 임의로 끼워 넣지 않는다. `장소.md`의 모든 장소가 첫날부터 자동 추천되는 것은 아니다. 장소 조사와 앱 화면 설계는 병행한다.

숙소 예약·1박 코스, 렌터카·자가용, 사용 중 AI 채팅은 첫 버전의 핵심 기능에 포함하지 않는다. **택시는 심야·대중교통 부재 시의 참고 대안**으로만 보여주며 실제 배차를 보장하는 추천 코스로 계산하지 않는다. 지역 추가가 쉽도록 같은 데이터 구조와 화면을 사용하되, 각 지역의 코스는 별도 검증 후 연다. 앱 배포 소스는 GitHub 비공개 저장소에 올렸고, Sites 버전 17을 별도로 배포했다. GitHub에 올린 지도 변경은 아직 Sites에 배포하지 않았다. 로그인과 기기 간 동기화는 추후 검토한다.

## 8. 앱 구성 검토 기준

- 홈의 여행지 카드에서 큰 대표 이미지와 추천 루트·여행지·여행 정보 탭이 있는 지역 소개로 이동한다. 지도 또는 계획표로 연결되며 검색으로 장소 상세에도 직접 들어갈 수 있다.
- 지도 검색·7개 유형 복수 선택·장소 카드·계획표/추천 루트 진입을 찾을 수 있다. 전체를 누르면 필터가 해제되고 지도/목록 전환 및 지역 중심으로 돌아오기가 가능하다.
- 휴대폰 홈 화면에 설치해 앱처럼 실행할 수 있고, 설치하지 않은 이용자도 웹사이트에서 같은 핵심 기능을 사용할 수 있다.
- 출발 지점은 직접 고를 수 있고, `현재 위치로 설정`을 선택하면 그때 위치 권한을 요청한다. 위치 권한이 없어도 직접 선택할 수 있다.
- `계획`에서 빈 시간계획표를 만들고, `추천 루트`에서 시간·필수 장소 등 조건에 맞는 여러 코스를 볼 수 있다. 이전에 논의한 네 가지 시작 방식은 이 두 진입 안에서 이용할 수 있다.
- 직접 만든 코스의 방문 순서는 사용자 동의 없이 바뀌지 않으며, 불가능한 구간과 대안이 구분되어 표시된다.
- 직접 입력한 장소가 데이터 목록에 없을 때도 코스를 편집·저장할 수 있지만, 그 장소가 포함된 구간은 가능하다고 확정하지 않는다.
- 추천 코스에서 예시 시간계획표를 열고 수정할 수 있으며, 빈 시간계획표부터도 작성할 수 있다. 시간표는 예시와 이용자 편집 내용을 구별한다.
- 시작 시각을 넣으면 자정까지 시간대 칸이 생기고, 칸을 누르면 직접 입력과 추천 장소 최대 3곳이 보인다. 추천 장소를 선택하면 그 칸에 들어가고 시간계획표로 돌아온다.
- 추천 루트의 코스를 선택하면 시간계획표에 넣을지 묻고, 넣은 뒤에도 일부 수정·삭제할 수 있다.
- 시작 시각을 늦춰 계획이 담긴 칸이 사라질 때 `옮기기 / 삭제하기 / 변경 취소`를 묻는다. 옮기기를 선택하면 전체 일정 밀기와 영향을 받은 칸만 직접 옮기기 중 고르고, 공식 시간 제한으로 삭제될 계획은 적용 전에 보여준다.
- 다음 장소의 길은 시간이 됐다고 자동으로 열리지 않는다. 이용자가 `이제 다음 장소로 이동`을 누르면 그 시각을 기준으로 지도 경로와 방문 가능 시간을 다시 확인한다.
- 시간계획표에서 앱에 있는 장소를 고르면 운영 종료·공식 입장 마감 또는 앱의 권장 입장 시각이 입력을 가리지 않고 표시된다. 앱에 없는 장소는 이름·위치·기타 메모를 한 줄씩 추가해 남길 수 있다.
- 18:00 폐관·공식 안내에 별도 입장 마감 표기가 없는 장소를 16:00에 방문하는 계획은 앱의 17:00 입장 권장 시각 때문에 제외되거나 방문 불가로 판정되지 않는다. 공식 마감과 앱 권장은 서로 다른 표기로 보인다.
- 코스 생성·시간표 수정·`이제 다음 장소로 이동`을 누른 때 운영시간·브레이크타임·공식 입장/주문 마감을 재검토하고, 충돌 또는 정보 부족의 이유를 표시한다.
- 시간계획표의 줄이나 안내가 많아져도 페이지를 세로로 스크롤하여 모든 줄을 볼 수 있다.
- 저장한 코스는 로그인 없이 현재 기기에서 다시 열 수 있고, 다른 기기와 동기화되지 않는다는 점과 데이터 삭제 시 사라질 수 있다는 점을 알 수 있다.
- 저장한 코스를 파일로 내보내고 다시 가져올 수 있다. 가져오기 과정에서 기존 코스는 확인 없이 삭제되지 않는다.
- 인터넷이 끊기면 저장한 코스의 계획 글만 열 수 있고 지도·새 코스 계산·재계산은 사용할 수 없다. 최신 운영·교통 정보가 확인되지 않는다는 표시가 보인다.
- 하루 일정 안에서 도보와 검증된 대중교통을 함께 사용하는 코스가 제공된다.
- 이름이 붙은 코스 목록에서 시간·걷기·교통 부담을 비교하고, 선택한 코스 하나의 상세를 볼 수 있다.
- 상세 상단의 화살표를 펼쳐 다른 코스로 전환할 때 지도 홈으로 이동하거나 검색 조건을 잃지 않는다.
- 시작·종료 시각을 바꾸면 가능한 장소와 제외 이유가 함께 바뀐다. 자정 이후 일정은 결과·상세·저장 화면에서 모두 `다음 날`이 보이고, 실제 날짜의 운영 조건과 해당 교통편의 운행일 규칙을 적용한다.
- 늦은 시간에 일반 코스가 없더라도 `운행 종료 확인`과 `운행정보 부족`을 구분하고, 확인된 도보권 장소와 배차가 불확실한 택시 대안을 각각 표시한다.
- 상세 화면에서 방문 순서, 이동, 마감, 끝나는 지점이 한눈에 연결된다.
- 종료 지점 `선택 안 함`의 결과는 마지막 장소와 종료 예상 시각을 보여주고, 귀가 이동은 계산에 포함하지 않았다고 명시한다.
- 정보가 불확실한 장소·교통편은 가능한 코스로 단정하지 않는다.
- 지도 없이 목록만 봐도 코스와 주의사항을 이해할 수 있고, 모바일의 뒤로 가기와 입력값이 자연스럽게 유지된다.

## 9. 이어서 구체화할 항목

- 이후 버전에서 로그인과 여러 기기 간 코스 동기화를 추가할지.
- 현재 비공개인 GitHub 저장소를 나중에 공개할지.
- 코스 명칭을 붙이는 규칙: 지역·주요 경험·소요시간 중 무엇을 이름에 우선 반영할지.
- 사용자가 직접 만든 코스의 이름을 언제 입력·수정할지.
- 여러 코스의 정렬 기준과, 같은 조건에서 코스가 한 개만 나올 때 상단 전환 목록을 어떻게 표시할지.
- 시간계획표에서 이동·휴식 줄을 얼마나 자세히 기본 표시할지.

여행지 이미지 탭과 소개 팝업을 첫 화면으로 두고, 지역 선택 뒤 지도·`계획`·`추천 루트`로 이어지도록 반영했다. 시간대별 계획표, 실제 출발 때 길 보기, 하루 계획, 도보+검증된 대중교통, 이름 있는 코스의 상세 전환을 본문에 반영했다.
