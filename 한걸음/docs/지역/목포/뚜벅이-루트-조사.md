## 2. 파악: 위치·이동·시간 제약

[목포시 권역 안내](https://tour.mokpo.go.kr/tour/attraction/area?mode=reginListView&search_cate11=01)는 유달산·근대역사관을 같은 원도심 권역으로 묶는다. [시화골목 안내](https://tour.mokpo.go.kr/tour/attraction/area?idx=74559&mode=view&search_cate11=01)는 오르막의 좁은 골목을 설명한다. [목포시 관광 코스](https://tour.mokpo.go.kr/tour/tourguide/mokpocourse?idx=158&mode=view&order=like&page=1)는 더 넓은 역사 명소의 연결 후보이나 실제 도보 소요시간 자료는 아니다.

기존 `places.json`에는 장소 130곳 중 좌표 60곳, 자동 판정 가능한 구조화 운영시간 15곳뿐이었다. [카카오 주소 검색 API](https://developers.kakao.com/docs/ko/local/dev-guide)로 주소를 조회하고 응답 주소가 원문과 일치하는 52곳의 건물 대표 좌표를 추가하여 **130곳 중 112곳**을 지도에 표시한다. 1곳은 주소 일치 검증에 실패하여 추가하지 않았다. 주소 좌표는 출입구가 아닐 수 있다. 운영시간이 없는 곳은 열려 있다고 단정하지 않는다. 날짜별 운영표는 해당 날짜에 한해 참고하고 다른 주로 일반화하지 않는다.

2026-10-03에 로컬 카카오 도보 경로 API로 확인한 예시(출발·도착 좌표는 앱의 장소 데이터):

이동 기준: 일반 추천의 개별 도보 구간은 **실제 경로 1.6km/25분 이내**, 하루 누적은 기본 **8km 이내**로 제한한다. API가 실패하면 직선거리를 도보 거리로 단정하지 않고 보수적으로 1.55배·시속 3.5km를 써서 `추정`으로 표시한다. 출발지와 종료지를 모두 경로 계산에 넣고, 마지막 장소에서 종료지까지 가는 시간을 예약한다. 먼 출발지는 가까운 권역에서 시작하며 무리한 연결을 강제하지 않는다.

시간 기준: 시작과 종료는 사용자가 정한다. 자정 종료도 허용한다. 식사 시각은 고정된 점심·저녁 규칙이 아니라 입력한 시각으로 잡고, 그때 음식점 또는 카페만 넣는다. 영업정보가 없는 곳은 `방문 전 확인`으로 표시하며 확인된 폐점·브레이크·주문 마감은 제외한다. 한 권역의 후보가 떨어지면 빈 시간을 `자유시간/이동 여유`로 보여 주고, 다른 권역으로 도보를 강제하지 않는다. 야간에는 산길·데크·케이블카 탑승처럼 시간과 통제 확인이 필요한 활동을 자동으로 넣지 않는다.

### 파악 단계 판단

반복 방문 동선과 공식 권역, 앱 좌표, 실제 경로 측정으로 원도심·북항/고하도·갓바위/평화광장의 구분과 보행 상한을 정할 수 있다. 주소·영업 정보가 미확인인 장소는 조건부 후보로 표시할 수 있으며, 자동 검증에서 확정 운영 장소로 취급하지 않는다.

## 3. 후보 선택

사용자가 장소를 직접 넣는 시간계획표와 자동 추천 루트는 같은 장소 정보와 거리 기준을 사용한다.

1. **시간별 장소 3개:** 시간계획표에서 빈 칸을 열면 해당 시각의 후보를 최대 3개 제시한다. 앞 장소·출발지와의 거리, 방문 가능한 시간, 선택 테마를 함께 점수화한다. 세 곳이 부족하면 없는 후보를 채워 넣지 않고 이유를 보여 준다.
2. **식사 후보:** 맞춤 추천은 방문 우선순위와 동선을 먼저 정한다. 코스가 나온 뒤 점심·저녁 각각 동선에서 들를 수 있는 식당과 예상 시각을 최대 3개 보여 준다. 선택한 식당이 기존 방문지를 대신하면 그 장소를 표시한다. 영업시간 미확인 식당은 확인 필요로 표시하고, 식사를 추가해도 핵심 방문지와 도착 시각을 지킨다.
3. **테마:** 기본(후기에서 반복된 원도심과 장소 다양성), 역사·골목, 바다·풍경, 소품샵·책방, 음식, 카페 중 고른다. 소품샵은 `shop` 전체가 아닌 소품·책방 장소 ID를 따로 사용한다. 음식은 `food` 방문 비율을 높이되 한 식당에 연속 식사하는 코스는 피한다. 바다 테마도 서로 먼 북항·평화광장을 도보로 붙이지 않는다.
4. **루트 비교:** 같은 입력으로 최대 3개 코스를 만든다. 기본 동선은 출발→도착 길목 위주이며 결과의 `동선 바꾸기`에서 출발지·도착지 주변 위주로 다시 계산한다. 꼭 가고 싶은 장소와 동선 중 무엇을 먼저 맞출지 선택할 수 있다. 필수 장소가 불가능해 대안을 보여줄 때는 누락을 명시한다. 적합한 장소가 없어 생긴 시간은 자유시간으로 표시한다.
5. **종료 지점과 시각:** 기존의 `끝낼 시각`을 도착 위치에 도착해야 하는 시각으로 사용한다. 마지막 장소에서 도착 위치까지의 이동을 포함해 검증한다.

### 후보 단계 판단

후기에서 반복된 원도심과 공식 권역, 날짜별 장소 정보의 신뢰 차이, 실측한 걸음 한계를 모두 반영하는 후보 규칙을 선택했다. 이 규칙으로 구현한 뒤 각 시간·테마·출발/도착지에서 실제 결과를 검증한다.

## 4. 제작

`travel-app/dist/route-engine.js`에 출발지·도착지·시작·종료시각·테마 조건을 받는 경로 생성기를 구현했다. 맞춤 추천에서는 코스를 먼저 만든 뒤 가능한 점심·저녁 식당과 예상 시각을 제안한다. 테마 추천은 식사를 자동 배치한다. 시간계획표에서도 종료시각을 직접 지정하거나 자정을 고른다. 빈 시간 칸을 열면 시간·거리·테마에 맞는 장소를 **최대 3개** 보인다. 자동 코스는 조건에 맞으면 최대 3개이며 여러 방문지, 식사, 마지막 도착 이동을 시간순으로 출력한다.

경로 계산은 [카카오 도보 경로 API를 연결한 앱의 로컬 프록시](../../../travel-app/server.py)를 먼저 쓰고, 실패한 구간은 거리 1.55배·시속 3.5km의 보수적 추정으로 명확히 표시한다. 한 구간 1.6km/25분, 전체 8km, 최소 두 장소, 종료 지점 도착을 모두 계산한다. 장소 종류별 체류시간은 식사 60분, 카페 40분, 소품샵 30분, 일반 명소 45분을 기본으로 한다. 확인된 휴무·브레이크·폐관·마감이 겹치는 장소는 버리고, 미확인 장소는 `운영시간 확인 필요`로 표시한다. 19시 이후 자동 선택에는 날짜별 또는 구조화 운영시간이 있는 음식점·카페·가게만 사용한다. 야간 장소가 부족하면 자정까지의 나머지를 자유시간으로 표시한다. 케이블카·배 이동을 도보 경로로 취급하지 않는다.

### 제작 단계 판단과 남은 한계

입력 칸과 경로 계산, 결과 비교, 시간계획표 반영, 운영 불확실성 표시가 연결되어 검증 가능한 결과물이 되었다. 새 장소 좌표는 건물 대표점이므로 출입구·경사·횡단 대기를 현장에서 확인해야 한다. 운영표의 날짜 범위는 2026-10-03~09이고 다른 날짜의 임시변경은 알 수 없다. 인스타그램·X의 공개 순서 자료를 확보하지 못한 한계는 그대로 남긴다. 이 조건을 명시한 상태에서 실제 API·화면 검증으로 넘어간다.

## 5. 검증 (2026-10-03)

### 검증 단계 판단과 미확인 사항

초기 네 조건에서 실제 도보 응답으로 거리 상한과 도착시각, 식사·테마가 맞았고, 화면에서도 필요한 입력과 한계 표기가 작동했다. 이후 19시 이후의 **날짜별 확인된 영업장**을 허용하도록 규칙을 보완했다. 보완 뒤 역 기본 코스(5.497km)와 해안·늦은 출발 코스는 다시 실제 경로로 확인했다. 소품샵 코스는 앞선 버전의 4.665km 실측 결과와 보완 뒤의 모의 거리 검사를 확인했으나, 마지막 실제 경로 재조회 때 로컬 프록시의 일일 안전 한도 **429**에 도달하여 보완 뒤 코스 전체를 다시 실측하지 못했다. 앱은 429 이후 추가 조회를 중단하고 추정 구간을 명시한다. 이 재확인은 조회 한도가 풀린 뒤 `node verify-live-route.cjs shops`로 수행할 수 있다.

**모든 날짜·장소의 영업을 보증하지는 않는다.** 공개된 운영정보가 없는 구보책방 등은 조건부 후보이며, 날짜별 표도 갱신이 필요하다. 주소 좌표 52곳은 입구가 아닌 대표점이다. 인스타그램·X 원문 동선은 자료를 확보하지 못했으며 개인 피드형 여행 SNS 2건으로 범위를 좁혀 사용했다. 아주 늦은 21:00~자정 시작처럼 검증 가능한 장소가 부족하면 억지 코스 대신 결과 없음으로 표시한다. 실제 출발 전에는 선택 장소의 당일 영업·보행 통제와 출입구를 재확인해야 한다.
