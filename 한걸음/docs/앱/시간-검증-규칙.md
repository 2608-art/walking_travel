# 시간 검증 규칙 — 초안

- 작성일: 2026-10-01
- 적용 대상: 추천 코스, 이용자가 만든 시간계획표, 계획 변경, `이제 다음 장소로 이동`
- 목적: 도착 시각에 방문 가능한지 판단하고, 운영시간·브레이크타임·공식 마감과 충돌하는 이유를 설명한다.

## 1. 기본 원칙

1. **운영시간, 브레이크타임, 공식 입장·주문 마감은 매번 확인한다.** 장소와 여행 날짜가 바뀌거나 계획 시각이 바뀌면 다시 검사한다. 실제 이동을 시작할 때는 그 시각과 예상 도착 시각으로 다시 검사한다.
2. **확인된 제한과 앱의 권장을 분리한다.** `폐관 1시간 전 입장 권장`은 안내다. 공식 마감으로 간주하거나 입력·저장·방문을 막는 기준으로 사용하지 않는다.
3. **정보가 없으면 가능하다고 단정하지 않는다.** 운영시간·브레이크타임의 존재 여부·공식 마감 중 필요한 값이 미확인인 장소는 `확인 필요`로 표시한다. 사용자가 직접 넣은 장소도 계획에서 지우지 않는다.
4. **이용자 계획은 자동 삭제하지 않는다.** 시간이 충돌하면 해당 줄과 이유를 표시하고 수정·대체·삭제 선택지를 제시한다. 시간 변경으로 줄이 사라질 때도 삭제될 항목을 미리 보여주고 확인을 받는다.
5. 시각은 **여행 지역의 현지 날짜와 시간**으로 계산한다. 자정 이후는 실제 다음 날짜의 요일·휴무·운영시간을 적용하고 화면에 `다음 날`을 표시한다.

## 2. 장소마다 필요한 시간 데이터

| 항목 | 용도 |
| --- | --- |
| 요일별 운영 시작·종료 및 휴무 | 해당 날짜에 들어갈 수 있는 기본 시간 구간 |
| 날짜별 특별 운영·임시 휴무 | 요일별 정보보다 우선 적용할 예외 |
| 브레이크타임 시작·종료와 적용 대상 | 주문 중단인지, 입장 중단인지, 시설 전체 이용 중단인지 구분 |
| 공식 마지막 입장·주문 시각 | 출처가 확인된 경우에만 제한 시각으로 적용 |
| 계획 체류시간 | 방문이 폐관 또는 서비스 중단 전에 끝나는지 검사하는 예상값 |
| 자료 출처·확인일·확실성 | 오래되거나 상충하는 정보를 확정 판정에 쓰지 않기 위한 근거 |

공식 마지막 입장·주문 시각은 `공식 안내에 별도 표기 없음`과 `조사하지 않아 미확인`을 구분한다. 별도 표기가 없으면 임의의 공식 마감을 만들지 않고 권장만 보여주며, 현장 입장 제한 가능성은 안내한다. 브레이크타임도 `없음 확인`과 `미확인`을 구분한다. 데이터가 상충하거나 오래돼 현행 여부가 의심되면 `확인 필요`로 낮춘다.

## 3. 판정 순서

1. 선택한 여행 날짜와 예상 도착 시각을 구한다. 코스 계획 때는 사전 계산한 이동·대기시간을, `이제 다음 장소로 이동`을 눌렀을 때는 **실제 누른 시각**을 출발 기준으로 쓴다. 이동시간 자체가 미확인이면 도착 시각과 방문 가능 여부도 확정하지 않는다.
2. 도착하는 **실제 날짜**의 특별 운영·휴무를 먼저 적용하고, 예외가 없으면 요일별 운영시간을 적용한다. 운영 구간이 자정을 넘으면 다음 날짜까지 이어지는 하나의 구간으로 다룬다.
3. 도착 시각이 운영 전이면 `아직 운영 전`과 기다려야 하는 시간을 보여준다. 휴무 또는 운영 종료 후라면 `운영시간과 충돌`로 표시한다.
4. 도착 시각이 **공식 마지막 입장·주문 시각**을 넘는다면 해당 활동의 공식 마감 충돌로 표시한다. 공식 마감이 미확인이라면 앱이 임의의 제한 시각을 만들지 않는다.
5. 브레이크타임과 겹치는지 검사한다. 입장·주문이 중단되는 시간에 새로 도착한다면 `브레이크타임 중`으로 표시하고 재개 시각을 제안한다. 이미 방문 중인 사람의 체류까지 금지하는지 불명확하면 임의로 퇴장을 가정하지 않고 `확인 필요`로 표시한다.
6. 예상 체류 종료가 폐관 또는 확인된 서비스 종료를 넘는다면 `계획한 체류시간과 충돌`로 표시하고 체류시간 단축·방문 시각 변경을 제안한다. **체류시간은 계획값**이므로 이용자가 더 짧게 머무는 선택을 할 수 있다.
7. 위 제한과 별도로 앱의 권장 시각을 계산해 짧은 안내로 보여준다. 권장 시각을 넘겨도 그 사실만으로 방문 불가·자동 삭제·입력 차단을 하지 않는다.

## 4. 결과와 화면 동작

| 결과 | 뜻 | 화면 동작 |
| --- | --- | --- |
| 시간상 가능 | 확인된 운영·공식 마감·브레이크타임과 계획이 충돌하지 않음 | 가능 근거와 남은 관람시간 표시. 당일 임시 변경은 별도 확인 안내 |
| 조정 필요 | 도착·체류·브레이크타임이 확인된 제한과 충돌하지만 시각을 바꾸면 검토 가능 | 충돌한 항목을 표시하고 기다리기·시간 변경·다른 장소 제안 |
| 확인 필요 | 운영·브레이크·마감 또는 이동시간의 현행 정보를 확보하지 못함 | 미확인 항목을 명시. 확정 추천으로 표현하지 않음 |
| 해당 시각 방문 불가 | 휴무, 운영 종료, 공식 입장·주문 마감 경과 등으로 해당 시각의 방문을 할 수 없음 | 이유와 가능한 다른 시각·장소 제안. 이용자 계획은 남겨둠 |

추천 코스는 확인된 제한과 충돌하는 장소를 `가능` 코스로 제시하지 않는다. 이용자가 만든 계획은 충돌해도 편집·저장할 수 있으며 각 줄에 상태를 남긴다. 단순한 `권장 시각 경과`는 위의 불가·삭제 사유가 아니다.

## 5. 시간 변경과 실제 이동

- 계획 시작 시각을 늦춰 앞쪽 시간 칸이 사라지고 그 칸에 계획이 있으면 `계획을 옮기기 / 삭제하기 / 변경 취소`를 먼저 묻는다.
- `옮기기`를 고르면 `전체 일정을 밀린 시간만큼 이동 / 사라지는 칸의 계획만 다른 시간대로 직접 이동` 중 선택한다. 변경 후 모든 장소의 운영·브레이크·마감을 다시 검사한다.
- 충돌 때문에 삭제 대상으로 표시할 계획이 있다면 **적용 전** 장소명·변경된 시각·충돌 이유와 `이 계획은 삭제됩니다`를 보여준다. 이용자가 삭제를 확인하거나 시각을 다시 조정할 수 있다. 권장 시각만 넘긴 계획은 삭제 대상으로 삼지 않는다.
- 이용자가 장소에 더 머물거나 일찍 떠났다면 다음 장소 칸의 `이제 다음 장소로 이동`을 눌렀을 때 새 출발 시각으로 지도 경로·예상 도착과 시간 규칙을 다시 계산한다. 버튼을 누르기 전에는 예정 시각만으로 지도를 자동 실행하지 않는다. 다음 장소가 어려워져도 계획을 자동 삭제하지 않고 대안을 보여준다.
- 지도·새 경로 계산에는 인터넷이 필요하다. 오프라인에서는 저장 당시 계획 글과 확인일을 보여주며 현재 방문 가능 여부를 새로 확정하지 않는다.

## 6. 확인 예시

| 상황 | 판정 |
| --- | --- |
| 18:00 폐관, 공식 안내에 별도 입장 마감 표기 없음, 16:00~17:00 방문 | **운영시간상 가능.** `17:00 이전 입장 권장`은 안내일 뿐 16:00 방문을 막지 않음. 현장 제한은 확인 안내 |
| 같은 장소, 17:20~17:40 방문 | 권장 시각을 지났다는 안내는 가능. 그 이유만으로 방문 불가로 판정하지 않음 |
| 같은 장소, 17:30~18:30 계획 | 폐관을 넘는 30분이 충돌. 체류 단축·시작 변경 제안 |
| 15:00~17:00 주문 브레이크, 16:00 식사 도착 | 주문 불가 시간. 17:00 이후로 옮기거나 다른 장소 제안 |
| 공식 마지막 입장 17:00, 예상 도착 17:30 | 공식 마감 경과로 해당 시각 입장 불가. 앱의 권장 시각과 구분 |

이 규칙은 **시간 조건**을 판정한다. 실제 버스 결행·지연, 현장 임시휴무, 입장 대기 등 당일 변동은 사전 데이터만으로 보장하지 않는다.
