# 주소 기반 추천과 이동 구간 저장

적용일: 2026-10-04. 구현: `travel-app/dist/app.js`, `travel-app/dist/route-engine.js`, `travel-app/server.py`.

## 코스를 만드는 방법

1. 시작·도착 위치는 앱 장소를 선택하거나 온라인 주소·장소 검색 결과를 선택한다. 검색 결과는 임시 좌표로 사용하고 앱 장소 목록에 추가하지 않는다. 검색 결과가 여러 곳이면 이용자가 선택한다.
2. 출발·도착 좌표, 날짜, 시작/끝낼 시각, 필수 방문 장소를 추천 엔진에 전달한다. 외부 주소도 같은 계산 규칙을 사용한다. `custom` 식별자를 유지해 계획표로 옮길 때 주소와 좌표가 유실되지 않게 한다.
3. 출발→필수 방문→도착을 연결하고, 지역 내 등록 장소 중 영업 판정과 이동 조건을 만족하는 곳을 추가한다. 기본 길목 동선에서 결과가 없으면 출발/도착 중심을 차례로 시도한다. 방문 순서를 조정해 이동을 줄이고 전체 시간표를 재검사한다.
4. 최종 제안할 코스의 이동 구간을 경로 제공자에 조회한다. 알려진 실제 경로가 거리·시간 상한을 넘으면 그 결과를 거절한다. 연결 실패 시에는 기존 추정 표시를 유지한다. 도보 한 구간 1.6km/30분, 누적 8km, 끝낼 시각과 필수 방문 조건은 임의 주소에서도 같다.
5. 식당·카페는 결과에서 추천 시각 하나를 골라 넣는다. 기존 식사 시각을 보존하는 규칙도 같다.

이 방법은 코드에 저장된 계산 절차이며 주소마다 완성된 코스 전체를 공통 DB에 저장하는 방식이 아니다. 새로운 관광지·메뉴·영업 정보를 API가 자동으로 조사하는 기능은 포함하지 않는다. 현재 필수 방문 입력은 앱 등록 장소만 지원한다.

## 영구 저장 정책

| 양 끝점 | 공통 SQLite 읽기·쓰기 |
|---|---|
| 등록 장소 → 등록 장소 | 허용, 같은 방향·좌표 구간은 중복 없이 재사용 |
| 외부 주소 또는 현재 위치가 한쪽이라도 포함 | 금지, 요청 시 경로 계산 |
| ID가 없거나 등록 ID와 좌표가 다름 | 금지 |

- 서버가 `places.json`의 ID·좌표와 기본 목포역 좌표를 기준으로 판정한다. 브라우저의 저장 허용 주장만으로 저장하지 않는다. 장소 데이터 변경 후에는 서버를 재시작해 기준을 갱신한다.
- 온라인에서 찾은 주소가 등록 장소와 같은 건물이어도 앱 등록 장소로 선택한 것이 아니면 임시 주소로 처리한다. 임의 주소가 코스 양 끝에 있어도 중간의 등록 장소 사이 구간은 재사용한다.
- 브라우저는 중복 조회를 줄이기 위해 임시 주소 구간을 메모리에서 최대 60초 재사용한다. 새 코스 생성 때 임시 구간을 비우며, 메모리 캐시는 최대 256건이다. 추천 엔진의 요청 내 중복 구간도 좌표를 포함한 키로 재사용한다.
- 서비스 워커는 `/api/` 응답을 저장하지 않는다. 서버 접근 로그에도 주소 검색어·좌표 쿼리를 남기지 않는다.
- 이전 DB를 삭제하지 않는다. 이번부터 외부 주소 구간은 기존 행이 있어도 읽지 않는다. 사용자가 직접 저장하는 개인 계획표는 공통 경로 캐시와 별도로 유지한다.

## 검증

- `verify-route-cache.py`: 격리 DB와 HTTP 서버/경로 제공자 대역으로 등록 구간 동시 요청 4건의 API 1회·저장 1건, 중복 재사용, 역방향 별도 저장, 외부·현재 위치·ID 없음·좌표 불일치 저장 제외, 이전 임의 구간 읽기 제외 확인.
- `verify-custom-address.cjs`: 외부→등록, 등록→외부, 외부→외부 코스 생성과 끝낼 시각·누적 거리, 브라우저 요청 ID 검증·동시 재사용·60초 만료, `custom` 좌표 전달 확인.
- `verify-route-improvements.cjs`: 동선 대체·식사 시각 유지 등 기존 개선 회귀 검사 통과. Python과 JavaScript 문법 검사 통과.
- 실제 브라우저: 온라인 검색으로 목포역 관광안내소(영산로 98)→해안로 249를 선택, 10:00~18:00으로 생성. 코스 1개, 방문 11곳, 카카오 경로 합계 약 3.34km, 17:53 도착. 각 이동 구간이 카카오 경로로 표시됨. [화면](../../travel-app/qa/custom-address-route-2026-10-04.jpg).
- 로컬 DB는 시험 전 0건, 첫 코스 생성 후 등록 구간 10건/미등록 0건. 동일 코스를 다시 생성해도 10건/미등록 0건이며 서버 경로 요청은 12→14건으로 증가: 임시 주소의 양 끝 2구간만 재조회했다. 이번 서버 실행에서 API 실제 응답을 확인했으며 과거의 502 상태와 구별한다.

로컬 서버의 네트워크 실행 제한 해소 후 주소·경로 API는 정상 응답했다. 카카오 지도 SDK는 별도 연결 문제로 기존 Leaflet 화면을 사용했다. 실제 출입구·현장 영업·보행 체감까지 확인한 것은 아니다. 로컬에 적용했고 배포하지 않았다.
