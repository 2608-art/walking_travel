# 추천 루트 사용자 흐름 검증 — 2026-10-04

## 판단

기존 검사는 코스 생성·거리·도착 조건을 확인했지만 실제 이용 흐름의 결함을 충분히 찾지 못했다. 이번 검사에서 기본 동선의 결과 없음, 보조 코스의 되돌아감·점심 목록 없음, 먼저 고른 식사 시각의 자동 변경, 동선 선택 두 항목의 동일 동작을 발견했다. 현재 상태를 실사용 검증 통과로 보지 않는다.

## 확인 범위와 방법

- 로컬 앱 `http://127.0.0.1:8766/`, 날짜 2026-10-04. 기존 인앱 브라우저에서 장소명을 입력하고 검색 제안을 클릭해 출발·도착을 선택했다. 5종 출발·도착 조합에서 동선 변경·종료시각 변경·필수 장소·식사 선택·패스·왕복 역방향·계획표 보류까지 조작했다. 두 코스의 전체 화면 캡처로 지도와 번호 배치도 확인했다.
- 별도로 [재현 스크립트](../audit-route-journeys.cjs)에서 대표 입력 21개 × 동선 설정 3개 = 63조건을 실행했다. 이전 검사와 달리 화면 기본값인 `through`를 명시했고, 앱의 실제 `evaluate` 영업 판정 함수를 읽어 재사용했다. 총 89개 결과 코스의 필수 장소·중복 방문·체류/이동 겹침·도착·거리 합계를 검사했다. 이 수치는 브라우저에서 63번 직접 조작했다는 뜻이 아니다.
- [원본 계산 결과](route-journeys-2026-10-04.json)에 코스별 방문 순서·시각·거리를 저장했다. 자동 계산은 추가 API를 호출하지 않고 보수적 거리 추정치를 사용한다.
- 로컬 경로 API를 1회 별도 확인한 결과 HTTP 502, `카카오 경로 API에 연결하지 못했습니다.`가 반환됐다. 브라우저에서 확인한 구간도 보수적 추정이었다. 실제 도보 길, 출입구, 경사, 당일 영업, 현장 보행은 이번 검증으로 확인하지 못했다.

## 수정이 필요한 문제

### 1. 기본 동선의 결과 없음과 잘못 짚는 안내

갓바위→평화광장은 기본 설정에서 0개지만 출발지 근처 위주에서는 13:17 도착 코스가 생긴다. 스카이워크→역사관 1관도 같은 현상을 보였다. `generate`의 직선 진행률 제한은 출발→도착 선분에서 뒤로 벗어나는 관광지를 엄격하게 제외한다. 여행자는 주변을 둘러보려는 것이므로 직선 반대편의 짧은 우회까지 결과 전체가 사라지는 이유가 될 수 있다. 결과 없음 안내만으로는 조건이 실제로 불가능한지, 생성기가 탐색을 놓쳤는지 구분할 수 없다.

### 2. 긴 코스는 생기지만 목적지 반대쪽으로 되돌아감

역사관 1관→스카이워크 자정 코스는 노적봉·성옥기념관·역사관 2관 뒤에 비팡이네→코롬방제과점→고호의 책방→씨엘비베이커리→웨이브로 되돌아갔다가 유달산 조각공원을 거쳐 도착한다. 출발·도착 직선 약 1.35km와 코스 추정 5.06km의 비율만으로 오류를 판정하지 않았다. 문제는 사용자가 원치 않은 반대 방향 재진입과 마지막 산지 경유다. `generateAdaptive`가 도착지 근처 중간 지점을 새 목적지로 삼아 코스를 만든 뒤 원래 목적지에 이어 붙이는 과정에서 원래 목적지 기준의 진행 방향이 보장되지 않는다.

### 3. 같은 긴 코스에서 점심 선택지가 전부 사라짐

브라우저와 재현 스크립트 모두 점심 음식점·카페 0곳이다. 이 코스의 마지막 방문인 유달산 조각공원은 운영시간 미확인 상태로 18:35에 배치된다. 일반 생성 규칙은 운영시간 미확인 관광지의 17시 이후 배치를 제외하지만, `generateAdaptive`가 추가하는 마지막 장소에는 이 규칙을 적용하지 않는다. 식사 삽입 검증은 뒤쪽 방문 모두에 다시 같은 규칙을 적용하므로 오후의 조각공원에서 탈락한다. 음식점이 실제로 하나도 없다는 결론으로 읽히는 문제가 있다.

### 4. 먼저 선택한 식사 시각이 후속 선택으로 바뀜

12:40 대명춘을 정한 뒤 10:05 혹호를 선택하면 점심이 13:20으로 이동한다. `기존 방문 유지`는 장소 삭제가 없다는 뜻으로 구현됐지만 이용자가 확정한 시각까지 유지하지 않는다. `previewMeal`이 뒤쪽 방문을 일괄 늦춘 뒤 `chosenMeals` 시각도 새 값으로 덮어쓴다. 예약 또는 약속한 식사 시각에는 문제가 될 수 있다. 재현 스크립트는 이 발견 때문에 종료 코드 1을 반환한다. 89개 코스의 시간·거리 기본 검사가 통과했다는 사실로 이 사용자 흐름 실패를 덮지 않는다.

### 5. 출발지 근처/도착지 근처 선택의 계산이 같음

대표 입력 21개에서 두 설정 결과가 모두 동일했다(결과가 있는 입력은 15개). 코드에서도 `start`와 `end`를 각각 구분하는 탐색 분기가 없고, `through`인지 여부만 다르게 다룬다. 특정 사례에서 우연히 같은 최적 코스가 나온 것과 다르다. 화면에서 고르게 한 의미를 계산에 반영해야 한다.

## 남은 범위

- 위 문제의 앱 코드 수정은 이번 검증 작업에 포함하지 않았다. 확인과 재현 자료를 먼저 남겼다.
- 저장된 전체 장소의 좌표 정확성, 온라인 주소 검색, 현재 위치 권한·오차, 오프라인 전환, 실제 보행 길·경사·교통·당일 영업은 별도 검사다.
- 출발/도착 지점은 체류 장소가 아닌 기준점으로 사용된다. 박물관을 도착지로 선택해도 그곳 관람시간이 자동 확보되는 것은 아니므로 이용자 안내가 필요할 수 있다.
- 계획표에는 기존 일정이 있었으므로 전체 가져오기나 새 계획 만들기로 덮어쓰지 않았다. 단일 장소의 충돌→보류 흐름을 확인하고 시험 항목만 제거했다.
- 배포하지 않았다.
