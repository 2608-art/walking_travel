# 추천 루트 수정 및 검증 — 2026-10-04

## 이번 변경

- 기본 동선은 출발→도착 길목 위주다. 연결 가능한 코스가 없으면 출발지·도착지 근처 중심을 순서대로 시도하고, 실제 적용한 동선과 자동 변경 이유를 화면에 표시한다. 출발·도착 위치, 끝낼 시각, 필수 방문 조건은 그대로 지킨다.
- 기존 보조 경로의 마지막 중간 지점 덧붙이기를 없애고, 출발·필수 방문·도착을 연결한 뒤 추가 이동이 적은 방문지를 끼운다. 출발/도착 중심은 각 기준점 주변을 실제로 다르게 탐색한다. 방문 순서 반전으로 이동이 줄면 운영시간을 다시 검사해 적용한다. 전역 최단거리나 되돌아감의 완전 제거를 보장하는 알고리즘은 아니다.
- 기본·대체 코스와 최종 경로에 동일한 영업·거리·도착 판정을 적용한다. 운영 미확인 야외 장소를 늦은 시간에 넣던 보조 경로 예외를 제거했다.
- 아침/점심/저녁 및 시간대 탭을 유지하면서 장소마다 해당 끼니의 추천 시각 하나만 표시한다. 방문 변경이 적고 이동이 짧은 시각을 우선한다. 가능한 음식점·카페 수를 임의로 줄이지 않는다.
- 이미 고른 식사 시각은 다른 식사 추가·동선 변경·역방향 전환 때 유지한다. 유지가 불가능하면 기존 코스를 보존한다. 음식점 추가로 운영시간이나 기존 식사와 충돌할 때는 필수·식사 방문을 보호하면서 일반 방문을 최대 2곳 줄이는 연결도 검토하고, 선택 전에 변경되는 장소를 안내한다.
- 음식 종류는 향후 업그레이드로 둔다. 검증된 `cuisineTags`를 연결할 수 있는 필터만 준비했으며 실제 장소의 메뉴 태그를 추측해 넣거나 음식 종류 선택 화면을 추가하지 않았다.
- 가능한 동선을 먼저 로컬 계산하고 제안할 코스 구간만 경로 제공자에 요청한다. 같은 요청의 중복 구간은 재사용한다. 기존 서버 영속 캐시는 유지한다. 식사 목록과 삽입은 여전히 추정 거리 계산이며 외부 API를 새로 호출하지 않는다.

주의: 전체 대안 코스 수는 89→70으로 줄었다. 중복 순서를 제거하고 지리적 범위·운영 규칙을 통일한 결과이며, 모든 입력에서 대안 개수가 늘었다는 뜻은 아니다. 근거리 사례의 기존 노적봉 ID가 성옥기념관 ID였던 오류도 바로잡았다. 따라서 그 1개 입력의 방문 순서는 동일 입력 비교로 해석하지 않는다. 기본 설정 성공 개수 증가를 만든 사례는 이 ID 수정과 무관하다.

통과 스크립트: `verify-route-conditions.cjs`, `verify-theme-day.cjs`(40조건), `verify-routes.cjs`, `verify-route-improvements.cjs`, `audit-route-journeys.cjs`. 식사 처리의 마지막 수정 후에는 뒤의 3개를 다시 실행했다. API 대역 검사에서 실제 경로가 거리 상한을 넘으면 추정값으로 덮지 않고 거절함을 확인했고, 중복 구간 요청이 없음을 검사했다. 이는 실 API 호출량 측정이 아니다.

## 남은 범위

- 이번 변경은 로컬 미리보기에만 적용했고 배포하지 않았다.
- 로컬 경로 API에서 502 연결 오류를 확인한 상태이며 화면의 이동은 보수적 추정이다. 카카오 지도 연결도 실패 안내가 나오며 기존 Leaflet 지도를 표시한다. 실제 보행 경로, 출입구·경사·당일 영업과 실 사용자 만족도 검증은 별도다.
- 스카이워크·북항·고하도 왕복과 멀리 떨어진 필수 장소 등 5입력은 여전히 결과가 없다. 현재 데이터와 도보 상한을 지키면서 연결할 수 없는 경우를 무리하게 성공으로 만들지 않았다.
- 18:00 도착은 계산상 종료시각을 만족한 결과다. 실제 신호대기·현장 체류 변동까지 보장하지 않는다.
