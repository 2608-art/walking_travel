# 추천 결과 지도 입력 검증 — 2026-10-06 (한국 시간)

## 범위와 변경

- 사용자는 Codex 브라우저에서 추천루트 지도의 실제 마우스 휠 확대·축소가 되지 않는다고 보고하고, 한 손가락 이동과 두 손가락 확대·축소도 요청했다.
- 추천 결과와 검토용 루트가 공통으로 쓰는 `initResultMap`에 휠 입력을 직접 처리하는 비수동 이벤트 리스너를 연결했다. Leaflet 지도에는 드래그와 터치 확대를 명시적으로 켰고, 지도 영역에 `touch-action: none`을 적용했다. 지도를 벗어난 페이지 휠 입력은 가로채지 않는다.
- 두 결과의 지도 설명에 휠·두 손가락 확대와 드래그 이동 방법을 표시했다. 장소·경로 계산 규칙은 바꾸지 않았다.

## 확인한 결과

- `node --check dist/app.js`와 `git diff --check` 통과.
- 별도 로컬 미리보기의 Edge에서 검토용 지도에 자동 마우스 휠 입력을 보내 확대 단계 15→17을 확인했다. 이어 반대 방향 입력 후 확대 단계가 15로 돌아왔다.
- 같은 화면에서 자동 터치 입력으로 한 손가락 드래그 뒤 지도 중심 좌표가 바뀌고, 두 손가락 벌리기 뒤 확대 단계가 15→16으로 바뀌었다. `dragging`·`touchZoom` 활성 상태와 계산된 `touch-action: none`도 확인했다.
- 기존 REST 설정을 로컬 서버 실행에만 전달한 Codex 브라우저 미리보기에서 2026-10-06 ‘처음 가는 목포’ 정상 추천 9곳을 만들었다. 지도에 스크롤 입력을 보내 15→18 확대, 18→15 축소와 새 조작 안내 문구를 확인했다.

## 한계

- 브라우저 자동 입력 검증이다. 사용자의 물리 마우스 휠과 실제 터치 화면에서의 손가락 동작은 아직 직접 확인하지 못했다.
- 처음 미리보기에서 2곳만 보인 이유는 분리된 워크트리 서버에 카카오 REST 키가 없어 실제 구간을 조회하지 못해 검토용 결과로 전환됐기 때문이다. 앱 데이터에서 방문지를 삭제한 결과가 아니며, 키를 코드나 Git 기록에 넣지 않았다.
