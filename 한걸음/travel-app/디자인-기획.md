# 한걸음 디자인 기획

## 현행 디자인 시스템 (2026-10-04 참고 이미지 재조정)

사용자가 **현재 기능·페이지 구조·여행지 상세 정보 순서·버튼 동작·지도와 데이터를 고정**하고 시각 디자인만 개선하도록 범위를 구체화했다. 아래의 기존 화면 흐름을 유지하며 재사용 가능한 [`design-system.css`](dist/design-system.css)를 최종 스타일 계층으로 적용한다. 기존 `diary.css`의 화면 배치·반응형 기준과 `app.js`의 이벤트 연결은 유지한다.

- 사용자 피드백에 따라 홈 목포 카드와 지역 표지는 원래의 `mokpo-card.webp` 일러스트로 복원했다. 이전 실사 중심 지시를 지역 대표 이미지 교체까지 확장한 판단을 되돌렸다. 장소 `p1`(유달산), `p8`(목포근대역사관 1관)의 실제 사진은 유지했다. [사진 출처·라이선스](dist/assets/photos/README.md)를 보존하고 홈에서 연결한다. 2026-10-06에 저작자·장소 대상·사용 조건을 확인한 실제 사진을 9곳에 추가해 총 11곳에 연결했다. 나머지 119곳에는 사용자가 허용한 관련 주제 예시 사진을 적용하고 실제 장소의 모습이 아님을 화면에 표시한다.
- 지역 카드는 현재 준비된 목포 한 곳만 표시한다. 기존 카드 그리드의 반응형 규칙을 유지하고 설명·여행 테마 태그를 간결하게 표시한다. **지역 찜/저장 기능은 기존에 없으므로 이번 UI 작업에서 추가하지 않았다.** 기존 계획표 저장 기능과 저장 메뉴는 유지한다.
- 실제 지도·마커 좌표·카테고리 색과 경로의 실제/추정·이동수단 구분은 그대로다. 검색·필터·버튼·하단 장소 카드의 외형만 통일한다. 경로 상태를 나타내는 실선/점선은 장식 목적으로 일괄 변경하지 않는다.
- 글꼴을 사이트 내부 파일로 제공해 외부 폰트 연결에 의존하지 않는다. [글꼴 출처와 적용 범위](dist/assets/fonts/README.md).

## 앱 아이콘·상단 로고 (2026-10-04 기본형 1번)

사용자가 아이콘·로고 후보 각각의 1번을 선택했다. 앱 아이콘은 크림 배경의 웃는 거북이 얼굴, 좌측 상단 로고는 투명 배경의 거북이와 손글씨 한걸음 조합이다. 이전 화살표 심볼을 대체하며 홈·지도·계획·저장 화면 구성과 동작은 유지한다. [자산·생성 프롬프트·출력 규격](dist/assets/brand/README.md).

## 최신 참고 이미지 분석과 적용

- 큰 차이를 색상보다 글꼴의 형태·제목 크기, 하단에 모인 풍경과 마스코트, 이미지 위의 크림색 종이 카드, 작은 꽃·구름·안내 말풍선에서 찾았다.
- 홈은 제목 → 깨끗한 검색 → 취향 → 기존 목포 카드 순서를 유지한다. 생성 배경은 [reference-landscape.png](dist/assets/diary/reference-landscape.png), 테마와 꽃은 작은 SVG 장식이다. [생성 모드·프롬프트·자산 기록](dist/assets/diary/reference-README.md).
- 참고의 다지역·찜·알림·공유·마이 메뉴는 현행 기능이 아니므로 만들지 않는다. 실제 지도는 원본 타일과 좌표를 유지한다. 제목·카드·색·라운드·여백·장식으로 유사성을 높이고 화면 캡처를 통째로 배경으로 붙이지 않는다.
- 검증: [참고 디자인 검증](qa/reference-design-validation.md). 원본 일러스트 복원과 디자인 개선을 구분한다.

## 기존 화면 구성 (2026-10-04 참고 이미지 반영, 이번 리뉴얼에서 유지)

- **클린 UI 70 : 스케치 30**을 시각적 기준으로 삼는다. 비율은 정량 측정값이 아니라 화면을 판단하는 디자인 원칙이다.
- 사용자가 배경만 바꾸는 수정이 아니라 참고 이미지의 **전체 구성과 정보 순서**를 요구했다. 기존 여행지 소개 팝업과 지도 아래의 인라인 장소 정보를 독립된 소개·상세 화면으로 확장했다.
- 홈: 연한 색연필 여행 스케치, 지도 보는 거북이, 검색창, 여행 취향, 대표 이미지와 설명을 분리한 지역 카드. 현재 제공 지역은 목포만이다. 취향 선택은 목포 소개의 해당 테마를 먼저 보여준다.
- 여행지 소개: 큰 지역 이미지 → 둥근 종이 모양 소개 영역과 거북이 → 추천 루트·여행지·여행 정보 탭 → 지도·계획 진입. 검증되지 않은 다른 지역이나 고정 코스 거리·시간은 만들지 않는다. 추천 루트 탭의 첫 카드는 **출발·도착 맞춤**으로, 기존 맞춤 코스 입력 화면을 바로 연다. 이어 준비된 6개 테마 카드가 나타난다.
- 지도: 실제 지도 위 검색·복수 분류 필터, 지도/목록 전환, 모바일 하단 가로 장소 카드와 계획 버튼. 데스크톱에서는 왼쪽 목록과 오른쪽 지도를 함께 보여준다.
- 장소 상세: 큰 이미지 → 장소명·위치 → 지도 위치·계획표·외부 장소 정보 → 방문 안내·운영시간·함께 둘러보기. 관련 장소는 같은 유형이며 근처라고 표시하지 않는다.
- 추천 결과: 조건 입력과 결과를 구별하고 지도/방문 순서 전환, 도보 거리·예상 일정·방문 수, 계획표 가져오기를 묶는다. 경로 실선·점선과 도보·버스 색은 실제 검증 상태를 보존한다.
- 계획표는 점선 시간축과 카드, 저장 화면과 입력·선택·버튼은 같은 크림·세이지 팔레트를 사용한다. 아이콘·검색·조작 영역의 가독성은 장식보다 우선한다.
- 실제 사진과 그림을 섞을 수 있는 구조다. 현재 지역 대표는 원래 목포 풍경 일러스트이며, 전용 사진이 없는 장소는 관련 주제 예시 사진을 표시하며 실제 장소의 모습이 아님을 밝힌다.

## 장소별 이미지 교체

- [`dist/place-media.js`](dist/place-media.js)에서 `places.json`의 장소 ID를 키로 `src`, `alt`, `kind`(`photo`/`illustration`/`example`), `credit`, `source`를 관리한다. 운영시간·좌표 데이터 재생성과 이미지 선택은 독립적이다.
- 예: `p8`은 목포근대역사관 1관이다. `./assets/places/` 아래 파일을 두고 이 ID에 연결하면 지역 여행지 카드·지도 장소 카드·장소 상세에 함께 반영된다. 예시 경로 자체를 실제 파일로 등록하지 않는다.
- 사진은 촬영 대상·출처·이용 허락을 확인하고, 그림은 해석한 일러스트로 관리한다. 파일이 없거나 로드에 실패하면 유형 이미지로 돌아간다. 현재 130곳 중 11곳에 실제 사진을 연결하고 119곳에는 서로 다른 예시 사진을 장소별로 연결한다. 예시 사진의 원본·저작자·이용 조건도 따로 기록한다.
- 이전 스케치 배경(현행 장소 유형 배경에 유지): [`dist/assets/diary/travel-sketch.png`](dist/assets/diary/travel-sketch.png). 실제 장소 지도나 사진이 아닌 일반 여행 배경이며 생성 기록은 [이미지 제작 기록](dist/assets/diary/README.md)에 있다.
- 검증 근거는 [화면 검증 기록](qa/diary-design-validation.md)과 [레이아웃 검사값](qa/diary-ui-report.json)에 남긴다.

## 이전 방향 (2026-10-02 대화, 변경 이력)

- 한걸음은 여행지를 고르고, 도보·버스·지하철을 이용해 가까운 거리에서 만족스러운 하루를 계획하도록 돕는 여행 앱이다.
- 첫 화면은 현재의 큰 여행지 이미지 카드가 가진 장점을 살린다. 여행지마다 눈에 띄는 이미지를 사용하고 여러 여행지를 고를 수 있게 확장한다.
- 여행지 카드에는 도시 이름과 특징을 짧고 구체적으로 표시한다. 긴 안내 문구와 불필요한 질문형 제목은 쓰지 않는다.
- 여행지 사진이 주인공이어야 한다. 코스와 이동 정보는 여행지를 선택한 다음 화면에서 자세히 보여준다.
- 지나치게 AI가 만든 것처럼 보이는 장식과 문구를 피하고, 실제 여행지의 분위기와 사용성에 집중한다.
- 구현 방식이 모호하거나 선택에 따라 결과가 크게 달라지면, 임의로 바꾸지 않고 사용자에게 먼저 확인한다.

## 마스코트 결정 (2026-10-03)

- 사용자가 제공한 가방을 멘 거북이를 한걸음 마스코트로 사용한다. 기본 원본과 여러 표정·상황 포즈가 담긴 원본 시트를 `dist/assets/mascot/`에 보존한다. 시트는 포즈 참고 자료이며 화면에서 잘라 붙여 사용하지 않는다.
- 첫 화면에서는 여행지 사진을 가리지 않는 상단에 기본 거북이를 배치한다.
- 지도를 볼 때는 지도 포즈, 코스를 찾을 때는 지도/발견/고민 포즈, 이동 중에는 걷기/버스 포즈, 계획표와 빈 저장 화면에는 각각 메모/휴식 포즈를 보조적으로 사용한다. 모든 포즈를 한 화면에 늘어놓지 않는다.
- 현재 실제 여행 계획 기능은 목포만 지원한다. 첫 화면에는 동작하는 목포 사진 카드만 표시하며, 다른 여행지는 데이터와 기능이 준비된 뒤 추가한다.

## 참고

- 앞서 만든 네 개의 첫 화면 시안 중 사용자는 첫 번째 ‘여행 엽서’를 상대적으로 선호했지만, 현재 앱의 이미지 중심 첫 화면이 더 마음에 든다고 밝혔다. 따라서 새 시안은 기존 이미지 카드 구조를 출발점으로 삼는다.
