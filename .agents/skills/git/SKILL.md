# GIT

이 스킬은 현재 프로젝트의 변경을 검토 가능한 Pull Request와 배포 결과까지 연결한다. 사용자가 "GIT스킬 해줘"라고 요청하면 이 전체 흐름을 시작한다. 특정 단계만 요청했다면 그 범위만 수행한다.

1. 프로젝트의 `AGENTS.md`와 관련 명세를 읽고 현재 요청의 범위를 확인한다. 명세가 아직 작성되지 않았거나 구현과 어긋나면 사용자 지시에 맞게 작성·수정한다. 요구사항이 불명확하면 먼저 질문하고 해당 결정에 의존하는 작업을 멈춘다.
2. 작업 시작 시 저장소의 원격 주소, 현재 브랜치·작업 트리, 원격의 최신 `main`을 확인한다. 원격이나 기준 `main`을 확인할 수 없으면 저장소를 추측하지 말고 사용자에게 묻는다. 최신 `main`과 작업 브랜치의 관계를 확인한 뒤 필요한 통합 방법을 정한다. 기존의 미커밋 변경은 사용자 작업으로 취급하고 범위가 불명확하면 묻는다.
3. 명세와 실제 변경을 대조하고 변경 위험에 맞는 검증을 수행한다. 이 프로젝트의 포트폴리오 작업기록도 실제 작업과 대조해 갱신한다. 이번 요청에 속하는 파일만 선택해 스테이징하고, 변경 내용을 다시 확인한 뒤 커밋한다.
4. 작업 브랜치를 원격에 푸시하고 `main`을 대상으로 Pull Request를 만든다. 제목·본문에는 변경 결과, 검증, 알려진 한계를 적고 생성된 PR을 현재 작업에 연결한다. PR 작성만으로 병합을 수행하지 않는다.
5. 배포가 요청 범위에 포함되면 프로젝트의 현행 배포 절차와 사용 가능한 Sites 스킬을 확인해 따른다. PR이 병합되지 않았을 때 배포할 소스가 작업 브랜치인지 병합 후 `main`인지 불명확하면 먼저 묻는다. 사이트와 공개 범위도 확인되지 않으면 묻는다. 배포 후 상태와 접근 가능한 실제 화면을 확인하고 버전·소스·검증 결과를 기록한다.
6. 최종 답변에 커밋, 브랜치, PR, 배포 상태와 확인하지 못한 사항을 구분해 알린다. 실패한 단계가 있으면 완료했다고 쓰지 않는다.

이 스킬의 존재 자체는 커밋·푸시·PR·병합·배포를 항상 실행할 권한을 뜻하지 않는다. 현재 사용자 요청의 범위를 따르고, 명세 작성이나 PR·배포 대상이 애매하면 `AGENTS.md`에 따라 질문한다.
